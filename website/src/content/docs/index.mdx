## Three-step setup

<div class="chord-steps">
<CardGrid>
  <Card title="1. Install" icon="download">
    macOS and Linux:

    ```bash
    brew install keakon/tap/chord
    ```

    On Windows, download the archive from [GitHub Releases](https://github.com/keakon/chord/releases), extract it, and add `chord` to your `PATH`.
  </Card>
  <Card title="2. Run from your project" icon="window">
    ```bash
    cd my-project
    chord
    ```

    The first run opens a setup wizard: enter an API URL, model name, and API key, or sign in with a Codex account.
  </Card>
  <Card title="3. Send your first task" icon="pencil">
    Type a task and press `Enter`:

    ```text
    Explain this project's main modules and how to run its tests. Do not change any files yet.
    ```

    By default, Chord edits files and runs commands without asking. File deletions through `delete` and deletions or moves through `apply_patch` require confirmation.
  </Card>
</CardGrid>
</div>

See [Quickstart](/chord/quickstart/) for other install methods, upgrades, and full first-run setup.

## Why Chord

<CardGrid>
  <Card title="Parallel agents" icon="random">
    After you [define subagent roles and grant the main role delegation permission](/chord/configuration/#agent-config), the main agent can delegate subtasks to subagents that run in parallel. Press `Shift+Tab` to switch between agents and see each one's progress and context.
  </Card>
  <Card title="Automatic model fallback" icon="setting">
    Model pools combine several providers and models and move to the next one when a request fails. One provider can rotate across several API keys.
  </Card>
  <Card title="Long sessions that fit" icon="list-format">
    Before each request, Chord trims old bulky tool output. Near the context limit, it compacts history into a summary and archives the original.
  </Card>
  <Card title="Approve before it runs" icon="approve-check">
    Set allow / ask / deny rules per tool and command, so risky actions wait for your confirmation.
  </Card>
</CardGrid>

### Measured comparison

Six coding agents completed the same [DeepSWE v1.1 task](https://deepswe.datacurve.ai/data/v1.1/tasks/httpx-streaming-json-iteration) with the same model (`deepseek-flash`). Chord was fastest and cheapest:

| Harness | Time | Estimated cost |
|---------|------|------|
| Chord 0.8.1 | **6m37s** <span class="chord-bar" style="--bar: 30%"></span> | **$0.052** <span class="chord-bar" style="--bar: 32%"></span> |
| deepseek-harness 0.1.5-rc.1 | 9m50s (1.49×) <span class="chord-bar" style="--bar: 44%"></span> | $0.079 (1.51×) <span class="chord-bar" style="--bar: 48%"></span> |
| pi 0.85.1 | 10m22s (1.57×) <span class="chord-bar" style="--bar: 46%"></span> | $0.086 (1.65×) <span class="chord-bar" style="--bar: 52%"></span> |
| codex 0.154.0 | 17m01s (2.57×) <span class="chord-bar" style="--bar: 76%"></span> | $0.139 (2.67×) <span class="chord-bar" style="--bar: 84%"></span> |
| mini-swe-agent 2.4.6 | 18m29s (2.79×) <span class="chord-bar" style="--bar: 82%"></span> | $0.125 (2.40×) <span class="chord-bar" style="--bar: 76%"></span> |
| claude code 2.1.272 | 22m25s (3.39×) <span class="chord-bar" style="--bar: 100%"></span> | $0.166 (3.17×) <span class="chord-bar" style="--bar: 100%"></span> |

After loading 200 messages, Chord uses just 39MB of memory (Claude Code: 216MB). See [Performance](/chord/performance/#measured-results) for token breakdowns and test conditions.
