# Changelog

This project follows Semantic Versioning-style releases. Before 1.0, releases may include breaking changes.

## Unreleased

### Breaking Changes

- Agent definitions no longer read `capabilities`, `preferred_tasks`, `write_mode`, or `delegation_policy`. Those keys were never enforced: they only appeared as labels on Delegate's agent-type list. Put routing intent in `description`. Whether a role may write files is still decided by `permission`, and Delegate still marks each choice with `empty_scope=allowed` or `non_empty_scope=required`. Leftover keys in existing agent files are ignored.
- Headless `compaction_status` events no longer carry the `model_downshift` trigger: compactions started by a move to a smaller window are reported as `usage_driven`. Filters matching on the old trigger value should match `usage_driven` instead.
- Headless question handling changed shape. A `question_request` no longer carries `default_answer` or `timeout_ms`; it carries `deadline`, the absolute RFC 3339 time at which Chord will close the question (omitted when `question_timeout` is unset). Chord no longer treats the first option as a default to fall back on. The `question` command now takes `reason` (`answered` or `declined`) instead of `cancelled`, and a closed question is announced through the new `question_resolved` event rather than inferred from a later snapshot.
- Worktree sessions are shared by every checkout of a repository. Sessions live in one store per repository, so a session started in a worktree is listed and resumed from the main checkout, and the other way around. Sessions that older versions wrote into a per-checkout store are not migrated and no longer appear in the list; a failed resume reports the old store path so you can copy the session directory across.
- A permission rule that names a repository path now applies to every checkout of that repository. A rule such as `write src/**: allow` configured in the main checkout also allows writes under `<worktree>/src/`, and no rule can allow a single checkout only: Chord evaluates repository paths through their repository-relative spelling, so an absolute path rule never matches them.

### Features

- `chord acp` serves the Agent Client Protocol over stdio, so ACP clients such as Zed can drive Chord as their agent. The client sends the working directory with `session/new`; answer text, thinking blocks, and tool calls (category, title, target file, raw arguments, output, and file diffs) stream back as `session/update`; cancelling a turn answers `cancelled`; and a `file://` resource link becomes the same `<file path="...">` context block the TUI produces. stdout carries JSON-RPC only, with each process logging to its own file in the logs directory. One `chord acp` process serves every session the client opens, up to `--max-sessions` (default 8), one child process per session, so each session keeps its own working directory, runtime, and MCP servers; `session/close` releases a session and its process. Permission prompts are not bridged yet: until they are, a tool that needs confirmation waits for Chord's own confirmation timeout. See [ACP agent mode](./docs/acp.md).
- New `chord sessions project <session-id>` command projects a persisted session into per-turn JSONL facts (turn boundaries, tool outcomes with result digests, tool-attributed file changes, compaction boundaries) for review and completion-report evidence. It is read-only and works while the session is open elsewhere; turn causes are reported as `user_message`, `inferred`, or `unknown` without guessing between a user continue and a background wake. `--out` refuses a path inside the session directory (or a hard link to a file in it) so a projection can never overwrite its source, and `--max-bytes` raises the 256 KiB JSONL cap when a long session needs it.
- New `question_timeout` (seconds, default `0`) controls how long the Question tool waits, independently of `confirm_timeout`; `0` means wait forever. The countdown covers the whole wait, including time a request spends queued behind another dialog, and it never adopts an answer: an elapsed question closes as `no_response`.
- Headless clients can subscribe to `question_resolved` push events. Each published question closes exactly once with a `reason` of `answered`, `declined`, `no_response`, `superseded`, `cancelled`, or `error`, so an integration can clear its pending question and tell an expiry or a supersede apart from a user decision.

- Docs now include a [Choosing models](./docs/model-choice.md) guide: decide whether what you already pay for reaches Chord, then split models by budget and role. Recipe and example pages still fill in a current flagship so the snippet is complete.
- Headless control-plane clients can now subscribe to three more push events: `session_switched` announces an in-band session change (handoff plan execution, `/resume <id>`, `/new`) with the new `session_id`, and `status_response.session_id` now tracks that active session instead of staying on the startup snapshot; `background_result` delivers a finished background job's durable result (`session_id`, `target_agent_id`, `message_index`, `content`), the only channel for JOB RESULT output that lands after the turn is idle; `context_notice` forwards durable context-pressure warnings (`session_id`, `level`, `message`, `message_index`) that have no other headless channel.
- New `compat.forced_tool_choice.auto_only` option downgrades any non-`auto` `tool_choice` to the backend default, for backends that only support `tool_choice: "auto"` and reject `required`, `none`, or named choices. Set it at the provider level with per-model override; an explicit `auto` is still sent unchanged.
- Headless state-carrying envelopes (event-loop pushes, command-path announcements such as `role_change` / `handoff_cancelled`, and `status_response`) now carry a monotonic `seq` so integrators can drop a `status_response` snapshot overtaken by a newer push. Snapshot versions are nonzero even before the first push and reset for each process. Any cached-state mutation bumps `seq`, even when the gateway did not subscribe to the corresponding push or the mutation has no push at all, so a later `status_response` cannot be overtaken by a snapshot copied before the mutation. State-carrying pushes also reach the wire in `seq` order (allocation and enqueue share one ordered section on both the event loop and the command path), so an integrator that only applies newer versions never drops an older announcement that will not be repeated; a `role_change` lost that way is never re-announced.
- New provider option `stream_total_timeout` (seconds) caps a single stream by wall clock, counted from when the response body starts, including Codex Responses WebSocket reads. `0` / omitted keeps today's behavior of no cap — a stream that keeps producing data is slow, not broken, and stays bounded by `stream_idle_timeout` alone — so setting it is opt-in. It exists for the one shape the idle timeout cannot catch: a stream that drips data often enough to reset the idle timer on every arrival but never finishes. On expiry the read fails with a timeout error, so the normal key/model retry path handles it like any other stream timeout.
- Background jobs now have a live surface in the TUI. While a job is running or stopping, the info panel shows a `JOBS` block with one line per job (label, elapsed time, and a clickable stop affordance), covering jobs your SubAgents started too; when the terminal is too narrow for the panel, the status bar carries a clickable `1 job` / `2 agents · 1 job` pill that opens the same list as an overlay. The pill and the stop affordance are click targets, so `ctrl+j` opens the same list from Normal mode without a mouse: `j` / `k` move the selected row and `Enter` opens its confirmation. Clicking `x` (or confirming from the overlay) opens a confirmation dialog with the job's id, label, command, owner, status, elapsed time, last-output time, and recent output; only `y` stops the job. Stopping a job this way notifies its owner that you stopped it instead of presenting it as a failure, and adds no toast of its own. The terminal title spinner also keeps turning while only background jobs are running.
- `delegate` now accepts an optional `result_schema`: a JSON Schema subset (`type`, `required`, `properties`, `items`, `enum`, `description`) that the worker's delivered result must satisfy, with `type` limited to `object`, `array`, `string`, `integer`, `number`, and `boolean` and an `object` top level. A schema outside that subset is rejected at delegation time instead of being ignored, while undeclared fields always pass. Chord checks the delivered payload — the inline `result` or the artifact behind `result_ref` — when the worker calls `complete`; a violation comes back for one corrected attempt, and a still-unsatisfied contract fails the task, records the violations in its settlement, and reports the failure to the owner and to `on_agent_error` hooks as `contract`. A `result_ref` whose content cannot be read back fails immediately, since a retry cannot repair the store. Delegations without a schema behave as before.
- `escalate` now requires a `kind`. `needs_repair` asks the owner for help and keeps the task running; `blocked` closes the task as failed with the worker's stated reason (owner card **AGENT BLOCKED**, `risk_alert` mailbox, `error_kind: blocked` on the `on_agent_error` hook) instead of parking the worker. A task may leave two `needs_repair` escalations unanswered: a third is refused back to the worker with a notice to make progress independently or close out with `complete`, which is what finally bounds a worker that keeps re-escalating the same blocker. Answering that escalation clears the count; other deliveries to the worker do not.
- New `chord doctor skills` command explains why a configured skill never reaches the model: per-skill integrity, load, `builder`-ruleset visibility, and declared-resource health, with `--json` and `--strict` modes. Skills can declare the files they depend on in the optional `resources` frontmatter field (paths relative to the skill root); missing resources never hide a skill but surface as a warning block in `skill` tool output and a marker on the TUI card.
- The agent can manage worktrees inside a session. `WorktreeEnter` creates or reopens a worktree (`name`, `path`, `base`, `branch`, and `reset_branch`) and moves the agent's working directory into it, so the shell, file tools, grep/glob, and LSP all follow; `WorktreeExit` leaves it and can delete the checkout; `WorktreeList` reports the repository's worktrees with their owner and dirty state. Each SubAgent has its own working directory, so one worktree can be reviewed while another is being edited, and a worker placed in a worktree keeps it as its identity: its completion report names the worktree, branch, and base it worked from.
- New `worktree.root` option creates worktrees inside the repository (`root: .chord/worktrees`) instead of the default location outside it under the state dir. Chord keeps a self-ignoring `.gitignore` in an in-repo root so the checkouts stay out of `git status`, and its own grep/glob skip that root.
- New `.worktreeinclude` file (gitignore syntax, default `.env*`) lists the gitignored files — local env files, machine-specific config — that Chord copies into every new worktree. Tracked files are never overwritten.
- New flags: `--reset-branch` reuses a leftover worktree branch that no worktree has checked out instead of failing, and `chord worktree remove --purge-sessions` deletes the session/export store that only older per-checkout versions wrote.

### Improvements

- The `question` tool result and its card now report each question's outcome — `answered`, `declined`, `no_response`, `superseded`, or `not_asked` — instead of listing only the selected answers, so you can tell an unanswered question from one you explicitly declined, and see which questions of a batch were never asked after an earlier one was not answered.
- Background job results now include their elapsed duration, and how long a running job has been silent shows up in `job_list` and the TUI's JOBS overlay (`no output 2m00s` before it prints, `quiet 5s` after) so a silent runner is observable without polling. `job_output(wait: exit)` explicitly reports whether its bounded wait timed out or was cancelled while the job kept running.
- A background job now covers the whole process group its command starts, not just the direct child: a command that exits while children it started keep running stays active until they exit, and those children stay under the job's `timeout_ms` deadline, `job_kill`, and session cleanup. `nohup … &` no longer escapes the job by outliving the wrapper that started it; a process that detaches with `setsid` / `setpgid` is outside the job again. A foreground call whose command exits this way comes back as a job handle instead of blocking the turn on those descendants, even with `yield_time_ms: 0`. A stop signals the group only while a member it recorded when the command exited is still in that group, and otherwise reports the teardown as unconfirmed instead of signalling a group number that may have been recycled. On platforms without process groups (Windows), a job still ends with its direct process, and a stop reports the teardown as unconfirmed because the descendants it may leave running cannot be observed.
- `job_list` lists only running and stopping jobs by default, with `include_finished: true` to also show the retained finished ones, and an active row reports how much of the job's deadline is left. A long session no longer buries its live jobs under finished entries.
- The status bar now counts down a wait instead of showing the time already spent. While every API key is cooling down it names the cause and the remaining wait (`↺ cooling down · 33s left`), and a retry round that pauses before its next attempt counts down to that attempt (`↺ round 12 · retry in 45s`). The cooling countdown targets the moment a request can actually go out rather than the next internal re-check, and a long wait such as a provider quota reset is shown in hours (`↺ cooling down · 2h15m left`); a round that re-probes immediately has no wait to count down and keeps showing its elapsed time. Narrow terminals drop the cause first (`↺ 33s left`), then the label (`↺ 33s`), rather than truncating.
- With a single model configured, a wait for cooling keys now runs to the key's real recovery time instead of restarting every minute: the wait ends at the earliest instant a key becomes usable. A long window (a confirmed quota reset instant, which the provider defines and `retry_after_max_s` does not bound, since that setting caps only a `Retry-After` hint) is waited out in one stretch, and the retry goes out as soon as the key is usable. Nothing re-probes the pool during that stretch, so a credential added mid-wait is picked up once the wait ends. With fallback models configured Chord still re-checks the pool at least once a minute, because a sibling model, a newly added credential, or a refreshed rate-limit snapshot can free up a request sooner. A worker waiting out such a cooldown is no longer reported to its owner as a stalled agent.
- A failed `lsp` query now includes the queried line and its neighbors with line numbers, so a position that landed off the identifier (a line number one off, pointing into the comment above a declaration) is visible without rereading the file.
- Read-only tool calls in one message now share one parallel batch instead of splitting it in two: `job_output`, `job_list`, `skill`, `view_image`, and `read_artifact` run alongside `read`, `grep`, `glob`, and `lsp`, and a `shell` command Chord already recognizes as read-only (such as `git status`) batches with them instead of acting as a boundary. A `job_output(wait: exit)` that is still waiting no longer holds back the reads and searches sent with it, two reads of different jobs never wait for each other, and two reads of the same job stay independent — each claims its own window of the job's new output.
- More shell commands now count as read-only for that batching: search and inspection commands such as `grep`, `find`, `sort`, `jq`, `diff`, `sed -n '1,20p'`, and `rg --no-config` (`rg` batches only with `--no-config`, because `RIPGREP_CONFIG_PATH` can inject `--pre`, which runs an external command), plus `git` / `gh` query shapes (`git blame`, `git stash list`, `gh pr view`, and similar), run alongside reads instead of serializing the turn. Pipes and `&&` / `||` chains of two reads (for example `git log | head -20`) batch as one, and `command` / `nice` unwrap one level. The judgment stays conservative and never changes permissions: unknown flags still serialize.
- A session working in a worktree keeps the project's context: instructions (`AGENTS.md`) and project skills come from the checkout the session works in — a branch can ship its own — and fall back to the main checkout for the gitignored copies a fresh checkout does not contain. Sub-agent definitions and memory are read from the main checkout, so a worktree session gets the same setup as the main one. Chord's own state — memory, plans, notes, and worktree records — is also written there, so a plan written from a worktree session does not disappear with the checkout it was written in. `chord --worktree <name> --continue` continues the repository's latest session with the worktree as the working directory.
- Resuming a session reopens the checkout it was working in. `chord resume <id>` and `chord --resume <id>` switch into the worktree recorded in the session and warn before falling back to the main checkout when it no longer exists. The session picker lists that checkout in a `Worktree` column, so sessions from different checkouts are distinguishable. Runtime cache is still kept per checkout.

### Fixes

- LSP `options` in the customization docs now nest gopls settings under a `gopls` key. Those keys are `workspace/configuration` section names, and the flat top-level form documented before was never delivered to gopls, so `staticcheck` and `analyses` configured that way had no effect; move them under `gopls`.
- Slash-command completion now runs the highlighted command after the list shrinks. Typing more of the prefix used to leave the selection index on the longer list, so the dropdown highlighted the last remaining row while `Enter` ran the first match — typically `/resume` instead of the custom command you had moved to.
- A question answer that arrives after the question's deadline is no longer accepted: the question closes as `no_response` and the late submission is rejected with an error, instead of letting a stale dialog report a success Chord never honored.
- A question dialog no longer decides its own fate when the countdown hits zero. It closes only when Chord reports the request resolved, so a question that already expired while queued behind another dialog is dropped instead of being shown again, and `Esc` or a submission from one question can no longer resolve a different one.
- Sending a new message while a question is pending in headless now supersedes that question deterministically: the message is accepted first, then the question closes with a `question_resolved` (`superseded`) event, so a resumed tool cannot slip a model request ahead of your message.
- Headless mode now drains already-published events before closing stdout, so a gateway that closes stdin still receives the tail of the session instead of losing the events emitted during shutdown.
- Checkpoint file reloading no longer follows a symbolic link out of the project root: such a reference is skipped instead of loading the linked file into context.
- Dialog overlays no longer show mismatched row backgrounds: the Cancel action in Delete Session, the inputs and Scope/Action rows in the rules add form, the handoff deny-reason input, and multi-segment rows in selector dialogs now stay on the dialog surface instead of falling back to the terminal background.
- Silent LLM retry telemetry no longer surfaces as a headless `error`: it emits no envelope and leaves `last_error` / `idle.last_outcome` untouched, so a turn that retries silently and recovers still reports `completed` instead of sticking on `error`. Terminal failures are still reported through the following non-silent error.
- Narrow `shell` allow rules now require review for command substitution, process substitution and unresolved quoting: a command containing `$(...)` or a backtick outside single quotes (double-quoted still counts), `<(...)` / `>(...)` outside any quotes, an unterminated quote, or a trailing backslash no longer auto-matches a specific `allow` pattern such as `"git *"`, and falls through to the next matching rule; a function body that executes in the same command string and any assignment that shapes a command — a prefix such as `PATH=` or `GIT_EXEC_PATH=`, or an assignment statement, `export`, or `declare` placed before it — are part of the matched source too, so neither can hide an unreviewed command behind a matching call site, while a rule written for the command's own text still decides: a `deny` cannot be pushed into a broader fallback, and a narrow `ask` cannot fall through to a broad `allow`. Plain redirection targets are not affected.
- A shell command that finished at the same moment the turn was cancelled keeps its real result: cancelling no longer relabels an already-exited foreground command as cancelled, so its exit status, output, and error survive instead of being replaced by a cancellation notice.
- Interrupting a streaming reply with `Esc` no longer splits that answer across two cards: the text the model had already produced keeps landing in the same card, thinking follow-ups stay in the same thinking card, and each card closes only after its producer's trailing batch arrives.
- Restoring a session after a context checkpoint no longer loses what a successful tool call produced: an elided result now explains that the checkpoint archived it instead of printing the raw placeholder, an `edit` card falls back to the requested replacement when its applied diff was elided, and the changed file still appears in the sidebar.
- Project memory now only records conclusions you stated (or that the session could not proceed without asking you) that a later session would still use without this machine's filesystem layout: model-discovered facts a later session could rediscover become review suggestions or are dropped, and session-local commit SHAs and machine-absolute paths are rejected from new records.
- A crash during a read-only shell command now restores as result unknown instead of never started, so a command that only looked read-only can never be retried as safe after its side effects already happened.
- Context-pressure notices stop being replayed once usage falls back below the reminder line: the durable notice (the reminder, the grace "compaction imminent" notice, or the externalization warning) is withdrawn together with its card at the next idle boundary, and is left out of requests until that rewrite lands, so the model no longer keeps reading a stale pressure warning at low usage. A later crossing delivers the full notice again as a fresh first delivery, and a usage-driven compaction request armed by a crossing that usage has since withdrawn from is cleared so the next gate does not start compaction from stale pressure. A session restored at low usage withdraws the notices it loaded just the same, and a notice freshly delivered after a restore or model switch is not swept by a withdrawal still pending against the previous window's rows.
- The agents panel no longer shows a nameless placeholder row while a `delegate` call is still receiving its arguments: a SubAgent row appears only after the delegation actually starts, so a failed or rejected delegate leaves no empty entry behind.
- Switching focus away from a long transcript and back while a reply is still streaming no longer freezes the pane at the content it held when you switched: the in-flight thinking or reply card keeps receiving its text, and the transcript stays at the tail.
- Cancelling a turn now also settles an agent that had finished its own turn and was waiting on a joined child task: when the cancellation stops the child, a parked owner with no remaining joined children is marked cancelled together with it instead of staying non-terminal until the session is restored.
- A SubAgent's context checkpoint now keeps the skills it loaded earlier across repeated compaction. The checkpoint was rebuilt only from the skills whose instructions were still in context, so a skill whose instructions an earlier compaction had archived disappeared from the list after the next compaction and the worker could no longer tell that the workflow had been in effect; each checkpoint now carries the previous checkpoint's names forward.

- A project-memory consolidation can no longer unindex a conclusion you stated yourself: a supersede that would remove it is refused with a warning and the entry stays, matching how retirement and promotion already keep your statements.
- A memory entry you delete from `MEMORY.md` stays deleted even when a later session re-derives the identical conclusion: the re-derivation counts as already known, so the removed line stays out of the index while the extraction still advances past it.
- The project-memory summary injected into each request is capped by the bytes it actually contributes: the limit is measured on the JSON-escaped text the reminder carries, so a summary dense in quotes, backslashes, or HTML-sensitive characters can no longer inject several times the intended budget.
- A panic during one project-memory extraction no longer stops background extraction for the rest of the session: each queue drain recovers on its own and releases the in-flight guard so the next wake retries. Permanent failures (unusable setup, or a commit that cannot proceed) now show as `MEMORY-FAIL` in the status bar instead of leaving the `MEMORY` pill to imply a healthy region.
- A detached job a SubAgent started keeps running when that worker is parked: parking used to stop its jobs, contradicting the job handle's promise that the command keeps running and its output will not be lost. Its completion is reported to the main transcript, so the result is still visible.
- With YOLO mode on, a model-driven context reset re-loads its state files again: the injection gate mirrors the execution bypass instead of evaluating the YOLO-filtered ruleset, which drops ordinary read rules and denied every path.
- Deterministic HTTP failures now end the model pool instead of retrying across it: 404, 405, 410, 414, and 415 are terminal on every provider (a gateway that starts answering 404 for a deprecated model otherwise retried with only silent telemetry instead of failing the turn), and 422 follows the 400 discipline. A fallback reason with no more specific class now names the status code (`http_404`).
- Aliased native-thinking targets resolve correctly: a `gemini-3` pin enables the Gemini 3 thought-signature placeholder without treating a family-only `gemini` pin as a version claim, and an unset `native_thinking` counts as `auto` again so the upstream family keeps being inferred from the model name instead of falling back to unknown.
- Background result cards are keyed by their durable mailbox row in both the live and rebuild paths: after a restart, a new job reusing an older `job-N` id gets its own card instead of overwriting the restored card of the previous run's job, while a re-delivery of the same row still updates the card it created.
- A `!` command that is still running when the transcript rebuilds keeps its card, and its output lands there when it finishes; if a session switch replaced that transcript in the meantime, the stale result is discarded instead of being written into the new session.
- Dialog overlays now stop one column short of the terminal's right edge, matching the status bar and the input separator: a full-width dialog that painted into the last column made hosts such as Ghostty add an extra frame line, and the cell-level diff then kept a stale row until a full repaint forced it away.
- Switching models while a request is still running now takes effect only when the next request starts: the running model and its tools stay in place while the response's tool calls execute, so a call such as `apply_patch` still runs instead of being rejected as unsupported by the newly selected model.
- Editing away a session's first user message no longer leaves the session list advertising the removed prompt: the preview and the recorded original request are cleared together with it.
- A mid-session prompt can no longer become a compacted session's original request: session lists and previews keep showing the prompt the session started with, and later compactions keep carrying that same prompt forward.
- The sidebar no longer mixes two models' data. A fallback attempt is not a switch: the model name changes only once that model actually emits output, so a fallback that is still waiting for its first token keeps the previous model's name, key list, rate-limit snapshot, and context window together. Aborting at that point leaves the sidebar on the model the next request will start from instead of pairing the fallback's name with the previously selected model's keys and window.
- Switching to a model with a smaller context window (or falling back to one) no longer holds the current request until context compaction finishes. Chord arms the automatic compaction and the next pre-request gate starts it in parallel with its own request, so the turn keeps running on the new model and only a rejection for context length suspends it behind a compaction; that gate's request carries the same context-pressure notice and compaction warning as any other threshold crossing. Previously the request was deferred until the compaction applied, which kept the turn idle for the whole compaction and dropped it if you interrupted the wait.
- GPT reasoning summaries now show each generated section heading (`**Heading**`) on its own line instead of gluing it to the text before it, including on backends that return every section in one part with the headings touching each other. A summary part that carries only such a heading — sometimes followed by an empty HTML comment — no longer shows up as an empty `Thinking` card.
- Context-pressure notices no longer stack two prompts on one request: switching to a model whose reminder line and threshold the current context already crosses attaches only the highest-pressure notice — the grace countdown, or the externalization warning on the request that starts the compaction — instead of the sticky reminder plus the switch-triggered warning.
- A message sent while context compaction was running no longer appears twice in the transcript: when the compaction rewrite redraws the transcript first, that message reuses the card it already drew instead of getting a second one.
- A background job read (`job_output`) is now recorded as started before it runs, so an interrupted session reports that read as an unknown outcome instead of assuming it never happened and replaying it. A replay misleads here: the read consumes the job's new output and claims its completion notice, so the retry returns an empty window that looks like a successful fresh read while the output the interrupted call had already taken is gone.

- A completion Chord rejected no longer shows a success card. `complete` arguments that failed validation, or a completion that arrived after the task had used up its recovery attempts, rendered a green success card while the transcript of the same call said the completion was rejected; the card now reports the error status, matching the failed outcome the transcript and the owner notification carry.
- A stdio MCP server whose `command` is the server process itself (for example `python3 /path/to/server.py`) is no longer killed the moment it finishes initializing. Chord tied the process to the connect attempt and cancelled that context as soon as the handshake succeeded, so such a server connected, vanished before `tools/list`, and never contributed any tool. It now stays connected until the session that owns it releases it or you disable it. Launchers that keep a child alive (`npx`, `uvx`) were unaffected.
- A cancel that arrives in the gap between a message being accepted and its turn starting is honored instead of dropped: the message stays in the transcript and its turn closes as `cancelled` right away, without a model request. Previously such a cancel was ignored, so a headless client that cancelled right after sending a prompt could still receive the whole reply while `idle.last_outcome` reported `cancelled`.
- `chord worktree remove` and `chord worktree finish` no longer delete the sessions and exports of the worktree they remove, so cleaning up a checkout cannot lose history. The branch is still kept by default.

## 0.8.1 - 2026-09-16

### Highlights

- Background work now runs through `shell`: a command that outlives its foreground budget is promoted to a job, and `job_output`, `job_list`, and `job_kill` manage it — `spawn`, `spawn_status`, and `spawn_stop` are removed.
- Time arguments are renamed and reunitized: `timeout_ms` and `yield_time_ms` count milliseconds, and a foreground `shell` yields after 90 seconds with a 10-minute deadline.
- Model-driven context checkpoints keep bounded completed-work records across resets, so a long session loses less progress to a reset.
- A context compaction no longer clears the composer, and tool cards keep their expanded/collapsed state across the transcript rebuild.

### Breaking Changes

- The `spawn`, `spawn_status`, and `spawn_stop` tools are removed; background processes now run through `shell`. Migrate `permission:` rules, hook `tools:` filters, and skill `allowed_tools` lists that name `spawn*`: start background work with `shell` and `run_in_background: true`, then manage it with the new `job_output`, `job_list`, and `job_kill` tools. A `spawn` permission rule no longer matches anything.

- The timeout defaults also change: a foreground `shell` now yields after 90 seconds and applies a 10-minute `timeout_ms` by default, while an explicitly detached job (`run_in_background: true`) with no `timeout_ms` has no hard deadline (the same default the old `spawn` had) and passes `timeout_ms: 0` to say the same thing out loud. The argument is also renamed and reunitized: `timeout` took seconds (max 600, default 30) and `timeout_ms` takes milliseconds (max 600000 foreground, or 21600000 with `run_in_background: true`; default 600000 foreground). Unknown arguments are ignored rather than rejected, so a call still passing `timeout: 60` does not fail — it falls back to the default instead of the 60 seconds it used to mean. Migrate every `timeout: N` to `timeout_ms: N * 1000`. The job handle and the completion notice name the deadline only when one applies.

- `web_fetch`'s `timeout` argument is renamed to `timeout_ms` and counts milliseconds instead of seconds: the old argument took seconds (default 30, max 120) and the new one takes milliseconds (default 30000, capped at 120000). Migrate every `timeout: N` to `timeout_ms: N * 1000`; a call still passing `timeout: 30` falls back to the 30-second default instead of failing, because unknown arguments are ignored.

### Features

- `shell` now covers background work instead of forcing a long command to block the turn. A foreground command that runs past its budget (`yield_time_ms`, default 90s) is promoted to a background job: its output is kept, and a completion notification wakes the agent when it finishes so it can do independent work or end the turn and be resumed by the completion. `run_in_background: true` starts a job immediately without waiting, and `timeout_ms: 0` starts a service with no hard deadline. Foreground commands stay capped at 10 minutes, while `run_in_background: true` allows `timeout_ms` up to 6 hours.
- New `job_output`, `job_list`, and `job_kill` tools manage background jobs. `job_output` reads only the output produced since the previous read, with a `wait` mode (`none`, `output`, or `exit`) bounded by the runtime so a slow job never blocks the turn and an expired wait never kills it. Repeated reads that find no new output are treated as polling (a notice first, then a rejection), and terminal escape codes are stripped from the output the model reads. `job_list` shows the jobs you can read or stop (your own, the main agent's, and those started by your direct owner), and `job_kill` stops a job without a completion notification. A folded `job_output` card reports the read on its header (`job_output job-8 · 2 new lines`, or `· no new output` for a quiet read), and a folded `job_kill` card shows `job_kill job-64 · Stop requested`, so neither hides its state behind the fold.
- Consecutive completion wakes with no user input in between are capped at 3; after that, later completions wait for the next user message.
- A model served over a Chat Completions gateway that translates the call into the model's native API now receives its `thinking.*` settings in that API's own shape: `extra_body.google.thinking_config` for Gemini, `thinking: {type, budget_tokens}` for Claude, `thinking: {type}` for DeepSeek / GLM / Kimi K2.x / Doubao, and `enable_thinking` for Qwen. The shape is inferred from the model name and needs no configuration, so one template works unchanged behind the gateway and on the model's native endpoint; `compat.chat_completions.native_thinking` forces a shape for aliased model names or turns the conversion off for endpoints that reject unknown body fields. Models outside those families keep using `compat.request_overrides.body.thinking`.
- A Chat Completions gateway that fronts a thinking model now keeps that model's native thinking state across tool-calling turns, and Chord replays it to the backend family that produced it instead of stripping it when the wire changes. Gemini thought signatures ride in `extra_content.google.thought_signature` on the step's first tool call, Claude blocks in the message-level `thinking_blocks`, and a signature captured through one provider's Gemini route is reused when the conversation continues on another provider, over Messages, or on the native API; a request that reaches another family strips the state rather than sending a blob the backend cannot validate. Missing state is repaired instead of shipped as a failure: Gemini 3 function-call history without a signature gets the documented `skip_thought_signature_validator` placeholder, and a Claude-backed route whose current turn lost its replayable blocks is called without the reasoning controls.

### Improvements

- Model-driven context checkpoints retain bounded completed-work records across resets and support explicitly retiring resolved issues and superseded decisions. Evidence references no longer need to be repeated across tool parameters, and claim summaries use a single compact view with their validity status.
- Archived evidence without classification can no longer support an `observed` claim. Obtain classified evidence or report the conclusion as inferred or unverified instead; provenance references alone do not prove a conclusion.

- Model-driven context management no longer treats a completed TODO list as a reason to checkpoint. The agent checks remaining work and delivers the final response directly when nothing else remains, avoiding unnecessary resets at task completion.
- A checkpoint is a continuation boundary, not a completion signal: applying it never closes the turn, and new user input or background results that arrive during the reset are processed by the continuation instead of being dropped.
- A model-driven checkpoint request identical to the last applied one is skipped when no new work or input followed that checkpoint (retries of the same request and context reminders do not count as progress), while any new input or work makes the request eligible for evaluation again.
- A model-driven checkpoint whose `evidence_refs` or `claim_evidence` cites an evidence ID the runtime cannot resolve is now rejected together with the list the checkpoint will accept in this context (first 8 IDs), like the observed-claim rejection already was: the continuation can cite a listed ID or drop the reference instead of inventing an `ev-` shaped one.
- Shared instructions now distinguish external files, web pages, images, command output, and MCP descriptions/results from authorized task instructions. This guidance applies to main agents and delegated workers even when model-driven compaction is disabled; tool permissions remain the enforcement boundary.
- Tool cards no longer share one folding rule. `write`, `edit`, `apply_patch`, `todo_write`, and `handoff` now stay fully expanded, like `delete` and the report cards: their body (diff, todo list, plan path) is content the model authored, so they carry no `▸` / `▾` marker and `Space`, `Enter`, or `o` does nothing on them. `read`, `grep`, `glob`, `shell`, `cancel`, and generic tool calls start collapsed and keep the fold toggle. A card with nothing more to reveal when expanded (the collapsed row already carries the whole content) carries no marker and does not toggle either, and the collapsed `shell` and `job_list` cards put the background job handle and the job count on the header line (`shell … · job-8`, `job_list · 3 jobs`).
- Tool cards no longer repaint the runtime's own argument notes inside the result body, where `Note: ignored unrecognized parameter(s): …` read like a line of command output or file content. The ignored argument is already named on the header (`ignored args.offset=10`), and the copied or exported text keeps the note. A session recorded before the runtime began storing those notes alongside the result still repeats the line in the body: the header names the argument from the argument audit, which older transcripts already carry, while the body only drops notes the result actually recorded.
- `lsp` cards keep their hit count on the header line (`lsp find references internal/tools/jobs_registry.go:771:6 · 7 references · 4 files`) like `grep` and `glob`, so a collapsed card is a single line and expanding shows only the locations. The count survives width clipping and the query location yields first, the same way a search card drops its parameters before its match count.
- A folded `cancel` card keeps its status on the header line, `cancel #7 · Stopped (workflow changed)`, instead of spending a second `↳ Stopped` row on it. A `notify` result that carries a structured handle no longer prints its status twice either: the `Result` section's `status:` field becomes the one place it appears, matching how a cancelled task's expanded card already works.
- Finished background `shell` work now renders as a collapsed `JOB RESULT` card that keeps each job's headline, adding a status line only when it carries something the headline glyph does not (a failure, a cancellation, or the elapsed time), and expands to the full command, status, and output.
- Elapsed times now read the same everywhere: whole seconds below a minute, zero-padded seconds above it, and hours once the duration passes one (`45s`, `3m05s`, `1h02m03s`). Tool cards, the status bar, the agent sidebar, the `job_list` table, a finished background job's `JOB RESULT` line, and the sidebar's TIME breakdown all share the format, so a 62-minute job no longer reads `62m03s` in one place and `1h2m3s` in another. Tool cards and the `JOB RESULT` line mark the duration with `⏱`, while the status bar lane and the agent sidebar keep their activity glyph (`⚙` while a tool call runs) and print the elapsed after it.
- Runtime notices fold to their badge line: `LOOP NOTICE` / `LOOP CONTINUE`, `REPLY RESUMED`, and the context-pressure cards (`CONTEXT PRESSURE`, `COMPACT WARNING`, `COMPACT IMMINENT`) start collapsed, showing `LOOP CONTINUE #2 ▸`, and `Space`, `Enter`, or `o` expands the full body. The generic `NOTICE` starts expanded because it carries command replies (`/role status`, `/models status`, `/mcp status`) and runtime diagnostics, and folds to the same badge line on demand. A notice whose body already fits on one line carries no marker and does not toggle, and sub-agent mailbox cards keep the worker model's full message visible.
- `compat.chat_completions.keep_reasoning_effort` keeps `reasoning_effort` and reasoning request overrides active for the whole turn when replayed assistant tool calls carry no `reasoning_content`. Endpoints that accept reasoning controls without a reasoning-content replay contract (Grok on the Chat Completions wire, for example) can now apply per-request effort tuning across a multi-request turn instead of only on the first request.
- The setup wizard now seeds `gemini-3.8-flash` (1M context, 64K max output) for Gemini endpoints instead of `gemini-3.5-flash`.
- A model-driven context reset now re-loads a bounded head of the files listed in `compact_context` `state_files` (and of the checkpoint's key files), so the continuation starts with the notes and plan documents that actually hold its recovered state instead of only their paths. A path is re-loaded only when the `read` permission rule currently resolves to `allow` (an `ask` rule is never silently auto-approved), so the reset can neither widen what the model could reach nor open a file the model was not allowed to read. A restored session keeps this behavior: the gate reads the live permission rules, not the session's read history, so an archived checkpoint's files still come back. `.chord/notes/` and `.chord/plans/` are eligible; memory records, session archives, and traces stay filtered. An empty `state_files` list remains valid.
- Checkpoint evidence packs stop spending their budget on tool failures a later success of the same tool has already recovered on the same targets. Only when the later success covers every path the failure touched does the superseded failure stop counting as a current blocker, so the `[Context Evidence]` excerpts carried into the next continuation stay focused on the failures that still hold up the work; successes whose effect cannot be attributed to a path never retire a failure.
- Deterministic checkpoint summaries no longer duplicate the latest user request inside the Todo State classification: the request text already appears under Current User Request in the same summary, so each anchor is carried once instead of twice.
- A partially applied `apply_patch` card marks each file it touched: the diff section of every group that landed carries `✓`, and every `Not applied:` entry carries `✗`. The errored card no longer prints the status-less `Targets:` list, so those two marks are what tells you which files changed and which failed.
- Shared guidance now asks for evidence that can tell a correct result from a plausible wrong one: before treating a key claim as settled, check whether the same evidence also fits an alternative that would change it, and find the smallest check that distinguishes them. The rule scales to the task — implementation and bug fixes verify the observable behavior the requirement implies rather than only the final output, investigation separates what was observed from what was inferred, code review confirms a reachable path and the guards around it, and analysis states its goal and constraints rather than treating evidence gathering as a build or test run. Guidance also now separates explicit requirements, observed facts, and your own assumptions when an ambiguity would change the outcome, and states that a test, analysis, or self-check produced under an assumption does not independently confirm that assumption.
- On macOS, a clipboard image/PDF attachment (`Ctrl+V` / `Alt+V`) is now read by a short-lived `osascript` process instead of the Chord process, which no longer loads the clipboard framework's AppKit: linking it costs about 7 MB of resident memory in every session, used or not. There is nothing extra to install — the reader runs the system `osascript` with a script built into `chord`, and the process exits, freeing its memory, as soon as the read finishes.
- Chord now targets `GOGC=50` when `GOGC` is not set, for the TUI and `chord headless` alike: the heap no longer grows toward the default target, so a 200-message session stays around 6 MB smaller (51.5 MB → 45.6 MB) and an empty session around 2 MB smaller. An explicit `GOGC` still wins, and `GOMEMLIMIT` is passed to the Go runtime unchanged — see [Environment variables: Memory tuning](./docs/environment.md#memory-tuning-gc) for how to pair it with a container limit.
- A fallback to a different model is announced as soon as the retry loop starts it, naming the failure reason (timeout, 5xx, context length exceeded, and other classified reasons) and the target model, instead of waiting until the new model emits its first token — which can be tens of seconds later, after key rotation and cooldown waits. While the fallback is being reached, the status bar keeps showing that target, reason, and elapsed time. Retries that stay on the selected model (key rotation, same-target backoff) remain silent in the error panel.
- Screen grids now hold 48-byte cells instead of 112-byte ones, which takes about 3 MB off an empty session and 3.5 MB off a 200-message session (in-use heap on a 50×200 terminal: 10.7 MB → 7.6 MB and 17.0 MB → 13.6 MB). Rendering is unchanged: recorded frames match byte for byte, and every render path allocates the same number of objects as before.

### Fixes

- Feature requests that describe a current limitation while naming the expected behavior no longer trigger the bug-triage workflow. English analysis and issue keywords now match on word boundaries instead of as bare substrings, so an adjective like `correctly` can no longer stand in for the analysis intent `correct` and route an unrelated request into failure investigation; the common inflections that matching still needs are listed explicitly, and the weak `correct` keyword is gone. The investigation outline is therefore shown only for actual investigation requests.
- Restricted roles no longer receive conflicting guidance to use unavailable search, editing, or coordination tools. Delegated workers without an escalation or notification tool are consistently directed to report blockers in their response rather than claim completion, and loop completion guidance consistently allows verification that cannot be run to be reported with a reason.
- MCP tool listings describe the integrations available to the current role rather than all connected servers. Server names and tool-listing errors containing Markdown or line breaks no longer alter the structure of the listing.
- Syntax highlighting no longer disappears from a multi-file `apply_patch` preview while the patch is still streaming. The preview fell back to plain text as soon as the patch mentioned a second file (or a move/rename), and only recovered once the call finished and the card rebuilt its diff.
- A context compaction no longer clears the composer: images and files you had already pasted, queued messages, and per-agent drafts survive the transcript rebuild that follows a compaction.
- Tool cards no longer change their expanded/collapsed state after a context compaction or a transcript rebuild. The rebuild used to match each new card against the old card at the same position, but the summary card that replaces the archived head shifts every surviving row, so a card could inherit an unrelated card's fold state — for example, an expanded Edit result came back collapsed. Cards are now matched by their own identity, and rewritten transcripts no longer borrow state from the transcript they replaced.
- Pressing `Up` in an empty composer recalls user messages only: after a context compaction it no longer fills the box with the summary text, and forking a user card can no longer load the summary either.
- Editing the tail user message of a compacted session no longer records the compaction checkpoint as the session's first message. The checkpoint stays marked as a summary, so session lists and previews keep showing the original prompt instead of the summary text.
- The `/role status` and `/models status` reports render one entry per line; the card's Markdown renderer used to reflow the indented lines into a single paragraph.
- Running `/mcp`, `/mcp status`, or `/mcp enable` / `/mcp disable` no longer leaves an echoed `USER` card in the transcript; these commands now route like the other local slash commands and report without starting a turn.
- A local shell command whose output outgrows the capture cap keeps its newest output, the same tail the `shell` tool keeps: the TUI's `!` command and the headless local shell both used a capture that stopped at the cap and dropped everything after it, so a long command's failure at the end (the part worth reading) was the part that got dropped.
- A `!` command or a headless `local_shell` command that daemonizes a process holding the output pipe no longer hangs its caller forever: the deadline terminates the whole process group, and the pipe drain is bounded so the command always returns with the shell's own exit status.
- The evidence references a context checkpoint declares stay resolvable for the next one. A checkpoint now re-renders every ID it lists, with the category and validity the runtime resolved, even when no excerpt of that ID is part of its evidence section — so a `compact_context` call that cites an ID from the checkpoint still in view is no longer rejected as unknown. A `compact_context` refusal that a later accepted call already replaced is no longer brought back with the new checkpoint either, so it cannot reappear as an error card right after a reset.
- A re-delivered background result keeps updating its existing card after a transcript rebuild instead of appending a duplicate, matching how the live path matches re-deliveries by durable identity.
- A model-driven checkpoint no longer drops the failed tool calls of the current turn. The reset archives the head, and a rejected call (for example a `compact_context` request the runtime declined) used to survive only as an excerpt inside the checkpoint: its error card disappeared from the transcript, and a fork of that generation no longer replayed the failure. The newest failed batches of the turn now stay as real records directly behind the checkpoint card; older failures remain only in the archive and the checkpoint's evidence pack. Only the failures keep their text: a successful result that merely shares the batch is replaced by a `[result elided by checkpoint: N bytes]` marker and its attachments are not carried back into the new context, so retaining a failure cannot spend the context the checkpoint just reclaimed.
- The closest-match hint that `apply_patch` and `edit` print no longer calls a line that merely ends earlier an empty line, and its rune offset is 1-based like the line number in the same sentence.
- The sidebar usage block no longer shows meaningless sub-1% ratio suffixes: the `Bytes` row hides `(↓0%)` when request-level context reduction saved less than 1% of bytes, and `Cache R` hides its share until it reaches 1%; the raw sizes are shown alone until then.
- The status bar and the input separator now stop one column short of the terminal's right edge. Writing into that last column makes hosts such as Ghostty add an extra line to the frame, and because the cell-level diff only repaints cells it believes changed, an empty `/resume` picker on a narrow terminal could leave a duplicated status row or a leftover dialog border on screen until a window resize forced a full repaint. That empty picker also opens straight into its empty state instead of flashing `Loading sessions...` first.
- Closing the `/` command list or the `@` file list no longer leaves a stray `╰` at the bottom-left corner of the message area. Nothing else on the row those lists cover changes when they disappear, so the cell-level diff never rewrote it; dismissing either list now forces one full repaint.

## 0.8.0 - 2026-09-11

### Highlights

- Project memory is here: a project-root `MEMORY.md` plus `.chord/memory/records/` capture reusable preferences, project facts, workflows, and pitfalls across sessions, injected as a bounded index and curated automatically once you opt in with `memory.enabled: true`.
- Long sessions manage context in two new ways: an opt-in `compact_context` tool lets the model checkpoint its state and continue on a compacted context, and compaction thresholds and pressure reminders are tunable per model — checkpoints keep the newest real user messages verbatim.
- A stream interrupted after it has produced text no longer throws that text away: the reply stays on screen and is saved as an interrupted reply, and the turn resumes through the normal key/fallback rotation with a `REPLY RESUMED` card.
- Upgrading touches existing configs and habits: role switching moved to `Shift+Tab` in Insert mode, `{` / `}` now jump between user message cards, and file-tool permission patterns are scoped to the session working directory — see Breaking Changes for the migration steps.

### Breaking Changes

- Role switching moved from `Tab` to `Shift+Tab` and is now Insert-mode only, while `Shift+Tab` in Normal mode keeps cycling the focused agent view. The mode decides which action the shared key performs: a role change is normally followed by typing a message, a view change by scrolling and reading. `Tab` no longer switches either — in Insert mode it now only completes a visible slash-command or `@`-mention suggestion and is otherwise inert, so the terminal's completion key can no longer rebuild permissions, invalidate the cached prompt prefix, and switch the model mid-typing from a single keystroke. On a SubAgent view, where a role switch does not apply, `Shift+Tab` cycles the view instead of doing nothing. A role switch is now announced with a toast (`role: planner → builder`) rather than only changing a sidebar label, and cycling a single configured role no longer pays for a ruleset rebuild and a recovery-snapshot write to land back on the same role. Both `switch_role` and `switch_agent` therefore default to `["shift+tab"]`; because only the action belonging to the current mode is consulted, that shared default is not a conflict. To restore the old bindings, set `keymap.switch_role: ["tab"]`: it keeps working in Insert mode, which is checked before the inert-`Tab` guard.
- Session IDs (`SID`) are now generated from the local wall clock as a 17-digit number (`YYYYMMDDHHmmSSfff`), so the embedded date/time reads as local time. Existing session IDs are not rewritten, so a sessions directory can mix local-derived and older UTC-derived IDs; outside UTC an older ID reads as a different wall time than it was created at. Session lists and `--continue` now order by the most recently observed activity (the newer of the `main.jsonl` and `usage-summary.json` modification times) rather than by SID, so the SID is no longer the ordering key. Chord does not scan full transcripts or maintain a project-level index; copied/restored files and activity that updates neither metadata file can still make the order approximate. `--continue` now also skips any session already open in another Chord process and continues with the next candidate (starting a new session if every candidate is owned elsewhere) instead of failing to start, and announces the skipped sessions with a one-time notice (a toast in the TUI, a `skipped_locked_sessions` field in the headless ready envelope, and the log); `--resume <id>` still reports an error for a session that is already open.
- The provider key `official_api` was split into `trust_http_400` (treat HTTP 400 as a terminal request error) and `retry_after_max_s` (longest honored `Retry-After` wait in seconds, 1–86400). Configs still containing `official_api` no longer fail startup: the key is logged and ignored. Migrate `official_api: true` to `trust_http_400: true` plus `retry_after_max_s: 86400`; migrate `official_api: false` to `trust_http_400: false` or omit it. Third-party providers now cap `Retry-After` at 60 seconds by default, so set `retry_after_max_s: 86400` explicitly if the old configuration relied on longer hints. `preset: codex` infers the trusted-400 and one-day cap settings automatically.
- `prompt_cache.ttl` is now validated at startup: `"5m"` and `"1h"` are accepted (and `"5m"`, the API default, is normalized to omitting the field), while any other value is a configuration error instead of being silently ignored. The TTL is also honored in `explicit` breakpoint mode, not just `auto`.
- The `preset: azure` provider preset was removed. Chord now configures Azure OpenAI Responses as a plain `type: responses` provider: set `auth_scheme: api-key`, `store: true`, `trust_http_400: true`, and `retry_after_max_s: 86400`, and drop the Codex identity headers with `compat.request_overrides.headers` set to `null` for `OpenAI-Beta` and `originator` (the one behavior the preset could not express with ordinary configuration). Configs still containing `preset: azure` are rejected at startup; migrating to the equivalent plain provider keeps the exact same wire behavior.
- The deprecated single-file `{path, patch}` argument shape of `apply_patch` no longer uses the `path` field: the wrapper is still tolerated for compatibility, but `path` is ignored and only the `patch` field is used, and it must carry the Codex `*** Begin Patch` envelope. The legacy `patch` tool name still normalizes to `apply_patch` for permission rules.
- File-tool permission patterns (`read`, `write`, `edit`, `apply_patch`, `delete`, `view_image`) are now scoped to the session working directory. In-cwd paths are normalized to cwd-relative form before matching, so a relative rule (`**`, `src/**`) covers the current directory and a bare `*` remains "any path". An absolute rule (`/Users/me/**`, `/**`) now only matches out-of-cwd paths and no longer covers files inside the working directory — write in-cwd rules in relative form (for example `**`) when that scope is intended. `./**` is accepted as equivalent to `**`.
- The `{` / `}` keys no longer alias `j` / `k`: they now jump between user message cards (turn boundaries), and `j` / `k` are the only next/prev-card keys. To restore the old behavior, bind `}` back to `next_block` and `{` back to `prev_block` in `config.yaml`.
- gpt-4/4o, gpt-3.5, gpt-oss, and o-series models now default to the `edit` tool instead of `apply_patch`: the `apply_patch` tool was introduced with GPT-5 in August 2025, so those families have no training signal and measured results are negative or untrained. Their tool surface changes from patch-only to edit with `write`/`delete` visible again. Every gpt major family from gpt-5 onward keeps `apply_patch` (the bare gpt-5, gpt-5-mini, gpt-5-nano, gpt-5-codex, any `gpt-5.*` name, and future majors like gpt-6; apply_patch is first-party Codex training data that stays in OpenAI training across generations) alongside `codex-auto-review`. Every default can be overridden per provider or model with `compat.apply_patch.enabled`.
- The `done` tool is now mounted only while a loop is running, instead of sitting on every request's tool surface. An ordinary session no longer carries its definition, and the model is no longer asked to choose between answering directly and calling a completion tool — a decision its description previously spent half its length arguing about, and which is now deleted. `/loop on` mounts it: late-mounted for the next request on providers that accept a mid-session additional tool (Responses-family models, Kimi dynamic tools), and through a one-time tool-surface rebuild (one prompt-cache miss) everywhere else; `/loop off` takes it back off. Loop entry is now gated on whether `done` *could* be mounted rather than on it already being visible, so the change does not make loop mode unreachable.
- A wildcard-only permission rule no longer reaches `done`. As with `compact_context`, the runtime mode that mounts the tool is the authorization, so an allowlist role (`"*": deny` plus a few tools) can run a loop without separately allowing the loop's own exit tool. Only a rule that names `done` still applies — write `done: deny` to reserve loop termination for yourself. Roles that previously had to add `done: allow` to use `/loop` no longer need it.
- Under YOLO, `handoff`, `delegate`, and `cancel` are now denied unless a rule names them directly. Previously the YOLO rule filter dropped every rule that did not name a protected tool, and a role that named none (any allowlist role, and any role whose only rule was `"*": allow`) filtered down to an empty ruleset, which the execution gate reads as "no permission configuration" and allows. Switching YOLO on therefore granted those roles the exact control tools they had denied, contradicting the documented promise that a broad `"*": allow` does not grant them. A role that needs one of these tools under YOLO must now configure it explicitly.
- `providers.<name>.compress` is now an encoding string (`gzip` or `zstd`) instead of a boolean. A leftover `compress: true` no longer enables gzip: it is ignored, request compression stays off, and `chord doctor config` reports it with a migration hint — set `compress: gzip` to restore the old behavior. `compress: zstd` sends zstd-compressed request bodies, the codec the Codex client uses for codex-backend requests; see [Provider request compression](./docs/configuration.md#provider-request-compression).
- `delegate` now requires an `expected_write_scope`, and read-only delegations are expressed by choosing an agent instead of by the removed `read_only` flag (passing `read_only` is now silently ignored). A read-only task picks an agent whose role denies the file-modifying tools and passes an empty scope `{}`, which is accepted only for such roles; every other delegation declares at least one of `files`, `path_prefix`, or `modules`. Calls that omit the field or provide an empty scope for a role that can write files are rejected instead of silently taking a global-exclusive scope, so existing delegation prompts and integrations must include the narrowest applicable scope.
- `expected_write_scope` is no longer an enforced boundary: the runtime no longer rejects file-tool targets outside the declared scope, no longer restricts Shell execution for read-only or scoped delegations, and no longer refuses a nested delegation whose declared child scope is broader than its parent's. A worker may now modify any file and run any command its role's permission rules allow, and the declaration is recorded for coordination only. Overlapping declarations between active tasks no longer reject a delegation either: the task starts and its handle carries a `scope_conflict` advisory (`suggested_task_id` / `suggested_action: serialize_or_worktree`) telling the owner to run the tasks serially, coordinate shared edits through `notify`, or give the new worker its own git worktree — use one of these when parallel workers would edit the same files. Concurrent writes to one file are still serialized per call to protect integrity, and a delegation that reuses an explicit `semantic_task_key` of a live task is still rejected with `already_exists`.
- Agent delegation limits are now bounded globally: `delegation.max_children` defaults to `10` and cannot exceed `64`, while `delegation.max_depth` defaults to `1` and cannot exceed `8`. Negative values and values above either ceiling are configuration errors rather than silently accepted settings.
- A role name no longer selects a built-in prompt block. Previously an agent file named `planner.yaml` silently received the planning block; now only `prompt_preset: planning` does, whatever the role is called. Add `prompt_preset: planning` to a custom role named `planner` to keep its current prompt — the built-in `planner` already declares it, so an unmodified installation is unaffected.
- `orchestration.waiting_main_min_wait_sec` and `waiting_main_max_wait_sec` are validated when the configuration loads: a maximum below the minimum is a startup error naming both values, instead of an inverted pair that silently expires parked workers on whichever clock happened to win. `orchestration.subagent_compact_usage` outside `0 < value <= 1` is likewise reset at load, so a project layer inherits the merged global value rather than falling back to the built-in default at runtime.
- The `notify_peer`, `task_collect`, `task_group_create`, and `save_result` tools (all part of the 0.7.3 release) are removed. Delegated-task outcomes still arrive through the runtime itself (AGENT COMPLETE cards and mailbox updates keyed by the stable `task_id`), coordination continues through the unchanged `delegate`, `cancel`, `complete`, `escalate`, and `notify` tools, and notices that previously targeted a sibling task now go through your owner via `notify` / `escalate`. `save_result`'s purpose moved into `save_artifact`: alongside `filename` / `content` / `mode`, it now accepts the mutually exclusive `result_type` + `result` pair (`result` must be a JSON object) to store the payload as an immutable content-addressed result under `artifacts/results/` and return a ResultRef that `complete` accepts directly as its `result_ref`. Migrate existing calls accordingly.
- The completion verification gate released in 0.7.3 is removed. `complete` no longer accepts a `verification_run` declaration (the command, for example `go test ./...`, whose recorded outcome the runtime previously checked before settling the task); restored sessions no longer gate a resumed continuation on verification provenance, and a completion settles on delivery without a verification step. Verification evidence is carried the ordinary way, as tool results and completion summaries, so existing completion prompts and integrations should simply drop the declaration.

### Features

- Headless control-plane clients can now query and switch the active main role — the remote equivalent of TUI Shift+Tab, for gateways that want to offer a role menu instead of relying on the agent to hand off. A `role` command (`list` / `set`) answers with a `role_response` envelope carrying the current role and the ordered main-mode role list (builder first, planner second, custom roles alphabetically), `status_response` gains a `current_role` field, and a subscribed client receives a `role_change` event after every successful switch. `set` rejects unknown roles, roles that exist only as SubAgent definitions, the already-active role, and any switch while a handoff decision is pending, returning the reason in `message`. In the TUI the same capability is now also reachable as a slash command: bare `/role` opens a role-picker dialog, `/role <name>` switches directly, and `/role status` prints the current role with the available roles; via `send`, headless maps bare `/role` to that `/role status` text and `/role <name>` switches directly.
- Headless clients can observe a pending handoff being discarded before a decision. A subscribed client receives a `handoff_cancelled` event (`request_id` plus a `reason`) when a newer turn, a session switch, or an auto-dismissing `send` supersedes the handoff, and `status_response.pending_handoff` returns to `null`, so an integration can dismiss its approval prompt instead of waiting on a request the agent has already dropped.
- A targeted `notify` can now resume a worker that failed. A failed task previously could not be continued at all (the resume policy named an explicit-recovery act that nothing implemented), so the only recovery was delegating the same work to a fresh worker that had to rediscover the context, even when the failure was in the wrap-up call and the finished deliverable was sitting in the failed worker's own history. The worker now comes back with that history and starts a new attempt; a cancelled task stays unresumable, because cancellation records a decision a message must not quietly undo — delegate again if the work should still happen.
- A delegated-task record becomes read-only only when it is settled — the worker's runtime is gone, the task was not parked for a later rehydration, and the record has reached a terminal state. A settled record stays readable: focusing it shows the transcript and the notifications around it, while anything that would continue, reply to, or change it is refused, so delegate the work again if it should continue. Live and parked tasks are unaffected and keep their existing follow-up paths: a live worker continues through a new attempt, and a parked task is rehydrated on demand.
- Agent configs can now select a built-in role prompt block by capability instead of by role name, and extend it instead of replacing it. `prompt_preset: planning` gives any role (under any name) the built-in planning block (plan-document naming and format, the direct-answer-versus-plan decision, handoff ordering, plan quality rules), which adapts its wording to the tools that role can actually see; it also suppresses the bug-triage block that would duplicate the planning workflow's own investigation outline. `prompt_preset: none` declines a built-in block, which is how a role named `planner` opts out. `prompt_append` adds text after whatever role prompt is in effect, so a role can add project conventions without taking over maintenance of the whole block — `prompt` / `system_prompt` still replace it outright. An unknown value is a configuration error rather than a silently empty prompt. See [Agent config](./docs/configuration.md#agent-config).
- Collapsed `spawn` cards now name the process ID in the result summary (`↳ Started · svc-64`) instead of only a bare `Started`. The ID is the handle every later `spawn_status` / `spawn_stop` call needs, so it no longer requires expanding the card to read. `spawn_stop` keeps its bare `Stopped` label because its ID is an argument the header already shows.
- Compaction thresholds can now be tuned per model and the pressure reminder is configurable. A model definition or `model_templates` entry can carry a `compaction` block with `threshold` and/or `reminder`; unset fields inherit the global `context.compaction` values (`threshold: 0` disables auto-compaction for that model only, and `context.compaction.reminder` sets the global reminder line with `0` deriving `min(0.60, threshold×0.90)`; `reminder: -1` disables the pressure reminder while keeping automatic compaction on). A reminder below the threshold fires when usage reaches `min(reminder, threshold)` (whichever line comes first) and one at or above the threshold does not fire separately (usage only reaches it on requests that already crossed the threshold — requests that would carry the deferral notice or the externalization warning anyway). Crossing the threshold starts the automatic compaction right away: it runs asynchronously in the background and applies at the next safe continuation boundary. While model-driven compaction is enabled, the first crossing in a window instead defers the start across two main-model requests, and every request inside that deferral carries a "compaction imminent" notice with the true remaining count (two requests left on the crossing, one on the final round); the context-pressure reminder also re-attaches on each request while usage stays above the reminder line (the full text once per window, a one-line pointer back to it afterwards) and goes quiet once the model calls `compact_context` in the window (whatever that attempt settles as), usage drops back below the line, or a durable apply / session switch / restore / model change starts a fresh window. The one-time externalization warning is carried by the request that actually starts the compaction (injected only while `model_driven` is enabled; the deferral is skipped once usage reaches 95% of the usable input budget, and ends when a model-driven checkpoint request settles without applying). The model may still submit `compact_context` while the automatic compaction is running or waiting to apply; its checkpoint wins and the runtime discards the automatic draft. Switching models applies that model's overrides and starts a fresh reminder window. The TUI colors the context usage display (sidebar Context value and gauge, status-bar percentage pill) from the same two lines (green below the reminder, orange/yellow from the reminder to the threshold, red at the threshold) and re-colors as soon as a model switch changes the threshold, instead of waiting for the next request. Each notice's first delivery in a window is also recorded as a durable context-notice message, so the model keeps the signal after the request that carried it is gone and a restored session rebuilds the same notice card; later requests in the window carry only the transient short line, and switching to a model whose threshold differs drops those durable notices because they describe the previous model's line. See [Context compaction](./docs/context-management.md#context-compaction).
- Model-driven context reset (experimental, opt-in): with `context.compaction.model_driven: true`, the main agent gains a `compact_context` tool it can call alone when carrying the current history forward costs more than restoring externalized state — the facts it needs later must already be written to files named in `state_files` or spelled out in the tool's structured arguments. A checkpoint is a costed state transition rather than a routine save, so a pressure-driven checkpoint at a safe stop is allowed while a task is still under way and does not require the current phase to be finished. The runtime validates the request, and at the tool-batch barrier builds a deterministic checkpoint (no summarization model call) archives the head, applies the checkpoint atomically, and continues the same turn on the compacted context. Low-gain requests (projected savings below 2048 tokens and 10% of the prepared surface) are skipped, as are requests made fewer than three main-model requests after the previous applied checkpoint; `state_files` are pure path references at checkpoint time and are never read or verified then (no read-permission bypass), but after the reset the runtime re-loads them when the current `read` rule allows, and the checkpoint's current user request always comes from your real messages. SubAgents never see the tool; a project-level `false` overrides a global `true`. The TUI labels a model-requested checkpoint distinctly from a usage-driven compaction and shows skip/failure reasons, `/stats` reports compaction lifecycle counts per stage and trigger (for example `applied/model_driven`, `skipped/model_driven`), and headless clients can subscribe to `compaction_status` events (with a `plan_id` on each outcome) to observe started and terminal results.
- Compaction checkpoints now keep the newest real user messages verbatim. Every checkpoint embeds the latest user-authored messages from the archived head (plus a dangling interrupted assistant reply when the conversation ends on one) in a `## Retained Recent Messages` section, within a small estimated-token budget (`context.compaction.retain_recent_tokens`, built-in default 4096, counting the message text only). When a model-driven archival checkpoint has no live tail, the assistant text that declared the `compact_context` call is kept the same way, so the analysis the model wrote just before the reset survives into the new window. Continuation-oriented compactions still preserve the most recent turns as raw messages after the checkpoint; the retained section covers the messages just before them and, for summary-only `archival` compactions, is the only verbatim remnant of the latest instructions — so the model resumes the current instruction boundary without re-reading the archived history files. See [Context compaction](./docs/context-management.md#retained-recent-messages).
- New `chord doctor config` command validates the global and project `config.yaml` files and reports every problem in one pass — malformed YAML, unrecognized keys, wrongly typed values, and invalid setting values such as an unknown `retry_backoff` or a negative diagnostics threshold. Config loading logs the value-level problems and starts anyway; this command surfaces them explicitly. Any problem exits with status 2, and `--json` emits a machine-readable report for scripts and CI.
- The planner role can now keep working notes under `.chord/notes/` (writes there are allowed like `.chord/plans/`), giving long read-mostly planning sessions a lightweight per-task externalization target they can list in `compact_context` `state_files`. The long-session guidance, the context-pressure reminder, and the pre-compaction warning name these role-permitted targets (`.chord/notes/` task notes or `.chord/plans/` plan documents) instead of leaving "write to files" unspecified.
- Notifications now pair the terminal notification with a terminal bell (BEL), giving an audible cue in the situation where most terminals (Ghostty, iTerm2, …) hide notification banners and only file them silently into the notification center. `desktop_notification_foreground: false` silences both the sequence and the bell while the terminal is focused. Bell audibility is terminal-dependent; the docs list how to enable bell sound per terminal (for example `bell-features = system,audio` in Ghostty).
- Manual MCP enablement is now session-scoped and durable: `/mcp enable|disable` persists the desired server set, session resume restores it before the first model request, and connection failure keeps the intent as enabled-but-unavailable for retry. Models can explicitly opt into cache-friendly runtime mounts with `compat.chat_completions.mcp_system_tools_message` or `compat.responses.mcp_additional_tools`; servers enabled before the first model request ride in the top-level tools array (there is no cache to protect yet), while later enablements are appended as declarations at fixed conversation anchors that Chord replays verbatim, keeps while disabled so execution remains blocked without rewriting the prefix, and reverts to top-level tools for the rest of the session run after a model switch, a resumed or forked history, or durable compaction. A brand-new empty session starts with dynamic mounts available again.
- Interrupted sessions now recover unfinished tool outcomes more precisely. A tool whose result was never saved is marked **not started** (the tool never began executing, so re-check preconditions and retry) or **result unknown** (the tool had started, so its side effects may be partially or fully applied — verify the current state before retrying). Chord writes the tool-call message to disk and syncs the started marker before running a state-changing tool, so an interruption cannot leave side effects it does not know were intended, and when the session directory becomes unwritable it pauses tool execution until persistence recovers instead of risking unrecoverable repeated side effects.
- Codex compaction uses the native remote compaction v2 protocol: the ordinary `/responses` streaming wire with an appended compaction-trigger input item and the `remote_compaction_v2` beta-feature negotiation header, replacing the legacy unary compact endpoint. Compact requests also retry across the model pool per provider, so a failed compact on the primary target falls back to other configured providers instead of aborting the compaction draft.
- Background compaction now streams live progress. Both compaction backends report transport bytes and stream events as they arrive, the status bar compaction pill shows them as a suffix (`■ 12s ↓ 8.0 KB · 3 events`) that keeps counting up across key, model, and summary-repair retries instead of showing only an icon and elapsed time, and a compaction request that receives no transport progress at all still refreshes activity while it runs.
- New project memory (Memory): a project-root `MEMORY.md` plus `.chord/memory/records/` stores reusable preferences, project facts, workflows, and pitfalls; all file references are project-root-relative and survive moving the project. New sessions automatically inject a bounded active index (fixed size regardless of record count), open detailed records only when relevant, and treat memory as untrusted, potentially stale background — it never grants permission or overrides the current request. Automatic extraction is off by default and enabled per machine + project with `memory.enabled: true` in config (project-level config overrides the user-level value); when enabled it runs only while the main agent is idle, compares new learnings with bounded project guidance and active memory to avoid duplicates or temporary Git/task state, keeps a preference only when you signal that it should persist instead of inferring one from a single in-task remark, replaces outdated index entries while retaining immutable provenance, scrubs sensitive content before both the model call and writing (best-effort), refreshes the current session's summary automatically after each commit, and shows a `MEMORY` status-bar indicator. The system prompt only gains the Memory discipline while memory is loaded and the extraction note only while extraction is enabled. Memory files are ordinary project files: Chord never stages, commits, or edits `.gitignore` for them.
- Memory curates its own index rather than only growing it. An entry that is no longer true, never belonged, or is already covered by your project rules is retired from the index while its record file remains as provenance; entries you stated yourself are exempt and only assistant-reported ones can be retired this way. Once the index reaches the size that fits the injection budget, an extra pass reviews the whole index on its own and consolidates it back under that size, so memory captured by an earlier or weaker model does not become permanent. Index order is injection priority — the newest entries lead, the tail is dropped when the budget runs out, and reordering `MEMORY.md` by hand survives later automatic writes. When a conclusion belongs in your project instructions or your own documentation instead of in per-turn memory, Chord writes a suggestion with a draft under `.chord/memory/promotions/` and unindexes the entry, except what you stated yourself, which stays indexed until you accept the suggestion; it never edits `AGENTS.md` or your docs itself.
- Interactive dialogs now land on the asking worker's view: when a delegated SubAgent's tool call needs permission or it asks a question through the `question` tool, the TUI switches focus to that worker's transcript before opening the dialog, so a permission decision arrives with the context the call grew out of instead of covering whatever transcript you were reading. Dialogs from the main agent keep the current view. Headless `confirm_request` / `question_request` envelopes now carry `agent_id`, so integrations can tell which agent is waiting.
- Card navigation now covers types with three bracket pairs: `}` / `{` jump to the next / previous user message card (turn boundary), `)` / `(` jump between assistant cards, and `]` / `[` jump to the next / previous card of the same type as the current one. All accept a `[count]` prefix, never land on error cards, and leave the viewport put when no matching card exists; `]` / `[` use the focused card's type, or the topmost card when nothing is focused.
- The message directory (`Ctrl+T`) opens with the cursor on the current card instead of always at the top, so Enter immediately jumps to where you were looking.
- Message-directory entries for tool cards now show the primary argument next to the tool name (`Tool: shell go test ./...`, `Tool: edit internal/tui/app.go`), so repeated calls to the same tool can be told apart at a glance.
- HTTP MCP servers can now send extra headers with every request via the `headers` config key — for example `x-api-key` for a service like Exa. A header value starting with `$` is expanded from the environment, so API keys do not have to be written into the config file; protocol-managed headers (`Content-Type`, `Accept`, `Mcp-Session-Id`) still take precedence.
- On OpenAI-compatible Responses endpoints, gpt-5-and-later family models now receive `apply_patch` as a freeform custom tool (`type: "custom"` with a Lark grammar) instead of a JSON function tool, so servers that support constrained decoding restrict the patch protocol during generation. The grammar only constrains the protocol skeleton and a gateway may strip it, so Chord's client parser stays authoritative and keeps its tolerant fallback path. All other models and non-Responses wires keep the JSON function shape, and the shape is configurable per provider/model with `compat.apply_patch.freeform`. Custom-tool calls are normalized to the canonical `{"patch": ...}` function-call shape at the wire boundary, so history replay, hooks, permissions, and audits behave identically across emission forms; a gateway that lowers the custom tool incorrectly returns an actionable error pointing at `compat.apply_patch.freeform: false`. Hosts that accept Responses but reject custom tools no longer have a built-in exception: configure `compat.apply_patch.freeform: false` there.
- `chord resume <session-id>` can now fork the session at a compaction boundary and resume the fork instead: `--fork-history` with no value selects the latest applied boundary, and `--fork-history=2` selects a specific one. Forking reproduces that generation's session state verbatim (the fork's `main.jsonl` is an unmodified copy of `main.pre-compress-N.jsonl` including its leading `[Context Summary]` checkpoint card; forking boundary 2 keeps boundary 1's summary at the top) and copies the earlier `history-1..N-1.md` compaction archives alongside so the checkpoint's history map stays resolvable and the model can read older content on demand. The boundary's own `history-N.md` is deliberately not copied: the forked `pre-compress-N` transcript still carries those messages inline, so copying the archive would only duplicate live content. Message text is preserved verbatim (session ids and paths inside it are historical facts, not rewritten), image/PDF attachments are relocated into the fork, and the new session's metadata records `forked_from` while keeping the source's worktree provenance and manual-MCP intent. Usage and runtime state start from zero — sub-agent transcripts, delegated-task records, mailbox state, background jobs, and artifacts under the source session's `subagents/` / `artifacts/` are deliberately not copied, so tasks delegated before the fork stay visible as message cards but cannot be continued in the fork. The original session is left untouched and does not need to be closed: just like `chord import`, forking reads only the archive files and writes a brand-new session directory, then resumes that session, so it also works for a session currently open in another Chord process.
- The initial setup wizard now defaults to GPT-6 Astra (`gpt-6-astra`), OpenAI's current flagship: a 1,050,000-token context window with 128K max output and `low`/`medium`/`high`/`xhigh`/`max` reasoning efforts (there is no `none`). The Codex OAuth path lists `gpt-6-astra` first as the initial model, with GPT-5.6 Sol/Terra/Luna and GPT-5.2–5.5 as fallbacks. Existing `config.yaml` files keep whatever model you configured; only fresh setups pick up the new default.

### Improvements

- Model-initiated dialogs (the permission / `done` confirmation, the `question` prompt, and the handoff agent selector) now bring the view to the agent that raised them instead of staying on whatever view was open. A request that arrives while another dialog is already on screen queues behind it and presents in arrival order instead of replacing the visible dialog: previously two agents asking at the same time could overwrite one prompt, leaving the other request unanswerable until it timed out.
- Tool cards whose subject is prose now read as one document instead of a collapsed preview: `done`, `complete`, `escalate`, `compact_context`, `delegate`, `question`, and `notify` cards are always fully expanded, their header carries only the tool name, and the report, description, objective, message, or question no longer appears twice — once as a header summary and once in the body. `o` / `Enter` / `Space` no longer toggles them. `cancel` keeps its collapsible card and its `cancel <task_id> (<reason>)` header index, and `notify` moved its target and kind into the body (`↳ Target:` / `kind:`) so its header stays a pure tool-name line. Cards indexed by an argument (`read`, `write`, `grep`, `handoff`, …) are unchanged.
- Compaction checkpoints state the recovery precedence explicitly: when the checkpoint conflicts with a newer source, the newer one wins — latest user message or Done rejection, then current runtime state (todos, subagents, background tasks), then the files on disk, then tool results still in this conversation, then archived artifacts, and only then the checkpoint's own text.
- Request-level context reduction no longer drops tool output for good. Whenever it replaces a payload with a summary, it first saves the full output to the session's `reduced-artifacts/` directory and appends the path to the summary, so the model (or you) can read back exactly what was trimmed. Identical payloads share one file. Reads are the one case where re-reading the file used to be the recovery route and no longer is: when the file was replaced by a whole-file write, a delete, or a change made outside the editing tools, the observed version is archived too, since re-reading would only return the new content.
- Progress and notice updates sent to the main agent now keep an idle main awake instead of being pure information: Chord keeps every update (not only each sender's latest), merges the pending ones into a single batch, and delivers them in arrival order as one extra main turn before it can report global idle — every arriving batch therefore costs one extra main turn and LLM request, and the idle event is held back until the batch has been delivered.
- Wake reactivations now have a bounded emergency pool controlled by `orchestration.max_bypass_runtimes` (default `4`). When normal, borrowed, and bypass capacity are all exhausted, Chord refuses the wake and leaves the durable message queued instead of creating an unbounded runtime.
- A SubAgent parked in `waiting_main` now expires using two clocks: the configured user-turn budget applies after the minimum wall-clock wait, and the maximum wall-clock wait expires it unconditionally. Configure `orchestration.waiting_main_expiry_turns`, `waiting_main_min_wait_sec`, and `waiting_main_max_wait_sec` to tune these limits.
- `edit`, `apply_patch`, and `write` now strip zero-width formatting characters and floating combining marks (zero-width space, zero-width non-joiner, joiner outside emoji sequences, word joiner, mid-stream BOM, soft hyphen; and a diacritic with no visible base, such as a stray macron that lands after a space) from the text they write, so a leaked invisible byte no longer lands in a file or breaks an edit's string match. A combining mark over any visible base is kept (diacritics on letters, math overlines on digits), and `apply_patch` cleans only the lines the patch adds — existing file content is never rewritten by the clean. The tool result reports exactly which code points were cleaned (for example `U+200B×2, U+0304×1`), so the model learns to stop emitting them.
- A failed `edit` now locates the closest matching block even when the target sits deep in a large file: the error names the file line, the similarity, and the exact differing lines (for example a missing `)` or a doubled `,,`), instead of only suggesting a re-read. It also names the first differing character by position and code point (`first mismatch at rune 4: your line has U+0020, file has U+0078`), and escapes invisible runes such as orphan variation selectors so they show up as `\ufe0f` in the hint instead of rendering identically to the clean line. When whole lines drifted past what those shown lines can reconstruct, the error hands over `read` coordinates (offset/limit) for the closest-match range so the model rebuilds old_string from a fresh bounded read, or falls back to a smaller 2-4 line anchor, instead of retyping the block from its (stale) memory. Previously the deep-window search exhausted its budget near the top of the file and fell back to the generic hint. When the same target file repeatedly fails approximate matching, the agent additionally appends a model-facing note after the second failure telling the model to read the target range fresh (or switch to `write`) instead of retyping the same old text from memory.
- `edit` and `apply_patch` tolerant matching now also folds a combining mark (U+0304 and the like) with no visible base (at the start of a line or preceded only by whitespace), a tokenizer leak that can creep into a copied heading ("`### ̄.2.1`") but never exists in a file at that position. A mark over any visible base (letter, digit, symbol, or punctuation) is preserved as potentially legitimate content (Arabic, Devanagari, Vietnamese diacritics, stacked marks, math overlines on digits), so legitimate combining text keeps matching normally.
- Interrupted turns no longer jump the viewport back to the prompt: resuming a session whose final turn was interrupted, and pressing ESC to cancel a live turn, both leave the viewport at the reply tail instead of scrolling up to the interrupted prompt.
- Emojis no longer leave a dark one-column block at the right edge of a card, and emoji presentation sequences (keycap digits such as `1️⃣`, variation-selector pairs) now render as their composed glyphs instead of collapsing to the bare base character. The screen parser keeps grapheme clusters whole and measures them with the same grapheme widths as the render pipeline, and card rows containing wide glyphs are repainted through an erase-to-end-of-line sequence, so the card background always reaches the true end of the line. Text after a mis-measured emoji can still sit slightly shifted within its line, and a few terminals without background-preserving erase can still fill erased regions with the default background — these are display-only artifacts the terminal ecosystem does not currently allow an application to fully solve; the troubleshooting guide documents them.
- Tool calls that fail argument validation now stay readable on screen: cards no longer lose their parameters when one field has the wrong type. File tools (read/write/edit/apply_patch) keep showing the path, and read/write headers additionally list every other argument that carries a value, including wrongly typed ones and unexpected keys — arguments left at their default (empty string, `false`, `null`) stay hidden so headers remain readable; TodoWrite and Question keep rendering their well-formed entries when one array item is malformed; Done/Escalate/Task/Cancel/Notify/Handoff recover their summary fields individually; long values are truncated. Validation errors also quote the offending value with its JSON type (for example `args.offset must be an integer, got string "1.0"`), so the model sees the same detail and can correct itself faster.
- Config loading now distinguishes broken files from bad values. Malformed YAML (a syntax error) prevents startup and is reported by `chord doctor config`. Unrecognized keys, wrongly typed values, and out-of-range settings anywhere in `config.yaml` are logged and treated as not configured while the rest of the file applies; in a project config an invalid leaf falls back to the inherited global value instead of clobbering it with a zero value.
- Thinking cards now align with user and assistant cards: the THINKING card and its role label start at the same left column as USER and ASSISTANT, instead of sitting indented to the right as a separate nested level.
- The info panel gains a `TIME` section showing where the focused agent's wall-clock time went — model streaming, tool execution, compaction, key/model cooldown, and waits for user confirmation or answers. Sub-second buckets stay hidden so short calls do not clutter the sidebar, and the section rebuilds from the usage ledger when a session is restored.
- When a stream is interrupted after the model already streamed body text, such as a mid-stream provider error event (e.g. `error` / `response.failed`), a truncated transport, or a read timeout, the produced text is no longer discarded and regenerated. It stays on screen, is saved to history as an interrupted reply, and the turn resumes from where it stopped by restarting the request through the normal key/fallback-model rotation. Resumption has no fixed round cap: it repeats while each interruption still leaves new visible text and stops when the reply completes, a round produces no body text, the turn is cancelled, or a non-resumable error ends the turn. Each interruption cools the failed key before the restart, so a transport that keeps truncating rotates across keys and fallback models and waits out cooldowns instead of restarting back-to-back. Pools whose models can resume from a trailing assistant reply need no extra input; other pools get a real continuation message appended right after the interrupted reply — the same text is sent to the model in this and every later request and shown in the UI as a `REPLY RESUMED` card before the resumed reply, so the card you see always equals what the model was told, and it survives session restore. An error event that explicitly signals an upstream/gateway stream interruption (`upstream_connection_error`, "upstream stream was interrupted") is treated as a deterministic provider-side outage and stops after a bounded number of retry rounds with a clear outage error instead of retrying forever. Interruptions that produced no body text (reasoning-only attempts, and attempts that had already started a tool call) keep the old silent retry, and failures that carry no usable output (bad request, context length) still discard the partial immediately.
- The info panel `MODEL` block now shows the provider on its own line and the model id with its `@variant` suffix on the next line, instead of squeezing `provider/model@variant` into one clipped line.
- The info panel `TOKENS` section now shows the focused agent's LLM request count (`Calls`) on its own line next to the accumulated token totals. The count comes from the persisted usage ledger, so it survives session restore and is not reset by context compaction.
- `apply_patch` now commits successful file groups even when unrelated files in the same patch fail, and reports each unapplied operation group with its cause instead of echoing the submitted patch back. The result clearly separates committed changes from unapplied operations, tells the model to rebuild the failed operations from current file contents and resubmit only those, and avoids repeating the same failure in a trailing `Error:` block. Move dependencies are directional: a failed move keeps later source/destination operations uncommitted, while a source group that fails after moving also rolls back operations that depended on its destination. Changed-file tracking and restored sessions reflect only the file groups that actually committed.
- `delete` follows the same partial-outcome contract: files removed before a failure count as committed changes instead of being discarded with the error, and deletions (including fully successful ones) now reappear in the changed-files sidebar after a session is restored.
- Delete confirmation rule suggestions now prioritize reusable parent directories instead of exact files, ranking directories that cover more paths still needing approval first. The picker always reserves the global `*` candidate, and when every requested path is inside the current working directory it also reserves a cwd-relative `**` candidate, so large multi-file batches cannot crowd out either broad choice; neither broad choice is preselected.
- Tool-result hook payloads (`on_tool_result`, `on_before_tool_result_append`, and each entry of batch `tool_calls`) now derive `path`/`paths` from the committed FileState when one exists: paths are resolved absolute paths, partially failed calls list only the files that actually changed, and SubAgents report the same payload shape as the main agent. Root-relative `path_filter` globs such as `src/**/*.go` now also match absolute payload paths inside the project root.
- Request-level context reduction now keeps scalar values and exact large integers in JSON-object summaries, samples JSON arrays across the first, middle, and last items, and reports the original line range for numbered-source output. Summaries remain bounded, and a JSON summary only replaces the original tool result when it is smaller.
- Provider retry pacing is now configurable with `retry_backoff: exponential | fixed | none` and `retry_delay_ms` (0–60000ms). It controls Chord-generated delays between complete model-pool rounds and ordinary HTTP 429 key cooldown when the response carries no `Retry-After` hint; a valid hint, bounded by `retry_after_max_s`, always applies verbatim ahead of the configured pacing. Confirmed quota reset windows and hard credential states still take priority. As part of this change, every HTTP 429 now takes the ordinary rate-limit path: a Codex usage-limit 429 carrying neither a retry hint nor an exhausted quota snapshot starts at the shared one-second exponential default instead of the preset one-minute cooldown (the preset branch still covers non-429 usage-limit errors), and a 429 that interrupts visible streaming output now applies the same pacing and rotates to the next key instead of retrying the same key without a cooldown.
- System prompts and tool descriptions no longer repeat the same steering rules, and each agent only sees guidance that matches its role and visible tools: the Done tool is only mentioned when it is visible and its required-signal source is named concretely (an explicit workflow instruction such as a loop anchor), loop completion requirements reference the Done report structure instead of restating it, SubAgents route open product decisions and necessary questions to their owner agent instead of being told to "ask the user", and agents are told that execution authorization is handled automatically by the permission system instead of being asked to assess risk themselves.
- Delegation guidance (continue an existing task with Notify versus create a new delegate, and parallelize only clearly independent write scopes) is now shown to every agent that can delegate, including SubAgents with nested delegation.
- Smaller prompt cleanups: the two post-compaction continuation notes merged into one reminder, the Read tool's truncation semantics are listed per state (`budget` / `stale` / `superseded`), the planner prompt now requires plan files to use `YYYYMMDD-<slug>.md`, Chinese bug-triage conclusion-comparison questions (哪个结论更对 / 哪个更正确 and variants) match by structure instead of a growing phrase list while ordinary review requests still do not trigger the failure-investigation workflow, and "be creative and thorough" for new files became a concrete instruction to cover implied edge cases without inventing extra scope.
- The default requested output-token cap (`max_output_tokens`) rises from `32000` to `64000`, so tool-heavy and reasoning-heavy turns are less likely to be truncated mid-response. The effective request limit is still the smallest of the global cap, the model's `limit.output`, and remaining context space. The global cap participates in the derived input budget only for models that declare no `limit.output`: those reserve more of the window for output, so their derived input budget shrinks and automatic compaction triggers earlier. Models that declare their own `limit.output` derive the budget from that value instead and are unaffected by the global cap. Models without a configured `limit.output` are requested at the new cap directly, so a backend whose real output capacity is lower and which validates `max_tokens` server-side may start rejecting requests — declare `limit.output` for such models, or set `max_output_tokens: 32000` to keep the previous cap.
- Read-only shell output and JSON documents are retained longer before context reduction: harmless inspection commands get a dedicated `context.reduction.shell_read_only_age_turns: 3` threshold, and JSON documents that are not line-delimited logs are kept until the stale-age threshold instead of being skeletonized early.
- Search summaries produced by context reduction now keep the full `path:line` location list within the byte budget instead of collapsing to a generic marker, so the model can still navigate to every reported match.
- Post-write LSP diagnostics now show paths inside the active tool working directory as relative paths, while files outside it keep absolute paths. This shortens `write`, `edit`, and `apply_patch` results and the model context without changing file identity inside the LSP runtime.
- Tool results attach post-write LSP diagnostics only when the edited files match a configured LSP server or produced direct backend diagnostics (such as Ruff's). Applying a patch that touches only files with no LSP coverage (a markdown document, for example) no longer surfaces cached diagnostics left over from files edited earlier in the session, which were easily misattributed to the current patch.
- Language-server workspace roots are now discovered per file: for each matching file, Chord uses the nearest ancestor directory (at or below the project root) containing any configured `root_markers` as the LSP workspace root, falling back to the project root when none matches. A server name can run one instance per root, so nested frontend packages (for example a `frontend/` inside a repository that is otherwise a backend project) get a language server rooted at the package, where its `node_modules`, `tsconfig.json`, and other package-local configuration live. Previously the repository root was always used, which left `typescript-language-server` unable to find its TypeScript installation in such setups. A single server name keeps at most 8 live instances, so sweeping a monorepo with more marker directories than that shuts down the least recently used instance instead of accumulating language-server processes; it restarts on the next file read under its root.
- When no Python interpreter is configured for Pyright, Chord now searches upward from the language-server workspace root for a project-local venv: it walks each ancestor directory, probing `.venv`/`venv`/`env` in every one, and stops at the Chord project root, instead of checking only the workspace-root directory itself. A nested workspace root (a `frontend/` package that got its own root through `root_markers`) therefore finds a venv that lives above it, such as the one at the repository root.
- Tool inputs that the model re-fetched after reduction are exempt from being reduced again (`recalled_input_protect`): re-reading a pruned file or re-running a pruned lookup durably protects that evidence for the rest of the loop.
- `yy` copying an `edit` tool card now shows the replacement as `## old_string` / `## new_string` sections instead of a unified diff, adding `## replace_all` only when enabled so default copies stay concise.
- `write` no longer refuses when the target file changed on disk after it was read. It proceeds with the write and backs up the previous non-empty content under the active session directory; only changes the model has not seen (external modifications) trigger the warning and backup, while content matching the agent's own last write or edit is treated as known and replaced without one. The tool result warns that the file changed and names the backup only when one was actually created, stating the source file next to the backup path so multi-file `apply_patch` backups are unambiguous — the model and the user see the same text, since a backup is best effort and a promise made to one audience must not be withheld from the other. A failed backup does not block the write and is recorded only in the local log. A file the model never read is backed up when readable and replaced with the write proceeding regardless, as described below.
- Building from source now requires Go 1.27.0+, and third-party dependencies were refreshed. One of them is not a released version: the JSON decoder on the LLM streaming path is pinned to an untagged upstream commit, because no tagged release admits Go 1.27 in its build constraints and a tagged one would silently fall back to the slower standard-library decoder. The dependency audit records the pin with the condition for dropping it.
- Parallel tool calls now leave the receiving state as soon as their arguments finish streaming instead of waiting for the whole response to end: on OpenAI-compatible Responses endpoints the provider's per-call arguments-done event ends the stream immediately, and on chat-completions wires the start of the next call is taken as the signal, so earlier cards show as queued and stop counting `N chars received`. On Responses endpoints this also lets qualifying read-only tools start executing as soon as their own arguments are complete, shortening the wait between the last argument byte and the first visible result.
- Context compaction now records archived history with absolute paths: the `on_after_compress` hook's `history_path` field and the archived-history references inside the compaction checkpoint use fully resolved paths (abbreviated as `~/...` when under the home directory) instead of project-root-relative paths. Consumers receive paths that work as-is, without resolving `../` chains, and deep project layouts no longer produce long relative references.
- Tool calls now tolerate extra fields beyond the declared parameters: as long as the required and known arguments are correct, Chord strips the unrecognized fields, runs the tool, and appends the ignored field paths to the result (for example `Note: ignored unrecognized parameter(s): args.offset`). Tool cards dim and strike through values that did not execute, including unrecognized fields and earlier values shadowed by duplicate JSON keys. This applies to arguments the model produced and to arguments you edit at the confirmation prompt. Missing required fields and wrongly typed values are still rejected, so the model can correct them immediately.
- Tool cards in an error state no longer show a redundant failure label (`Search failed`, `Failed`, `LSP query failed`, …) next to the error detail: error cards keep only the ✗ mark and the `Error:` block, while success and cancelled states still get their summary line (`2 matches`, `Done`, `Stopped`, `Cancelled`).
- `apply_patch` now auto-wraps a bare patch body into the Codex `*** Begin Patch` envelope when the caller omitted it but otherwise sent a valid current-format payload, so providers and gateways that strip only the outer marker no longer fail a call the model already formatted correctly.
- On models that support request-only dynamic tool mounts, enabling loop mode during an in-flight request may now late-mount `done` on the next loop request when the frozen top-level tool surface does not already contain it. Chord skips the late mount when `done` is already present, so the follow-up request keeps one `done` definition instead of duplicating it.
- `read` and `read_artifact` now treat `offset` as a 1-based start line (1 = the first line) instead of a 0-based skip count; passing `0` or omitting it both mean the first line, so a call that passes `1` for the top of a file no longer silently skips the first line. The tool card header and the confirmation summary hide the default offset (0 or 1), out-of-range errors suggest 1-based offsets, and the read card gutter starts at the requested line when the result lacks a range header.
- apply_patch tool cards now preview the patch while the model is still writing it: the card stays expanded during argument streaming and shows the growing patch text with `+`/`-`/`@@` syntax highlighting, marks each `@@` hunk with an inline separator, and keeps failed requested-patch previews distinct from applied diffs; this replaces the opaque character count, and once execution completes successfully the card switches to the final diff view.
- `edit` and `apply_patch` requested-patch previews now render the full patch instead of stopping at 20 lines, so the model and the user see the complete planned change while arguments are still streaming.
- `edit` and `apply_patch` result diffs now render in full instead of stopping at 200 lines; very large diffs are handled by the TUI viewport's fold/spill machinery, so the model and the user see the complete committed change.
- Compaction checkpoints now open with a **session anchors** block that is copied forward verbatim across recursive compactions instead of being re-derived: the session's original request, the standing constraints extracted from your corrections, and declarative constraints you stated (such as "keep the existing API behavior"). Later instructions that contradict an earlier constraint supersede it, and the superseded entry stays visible in the anchors block with a `~ ` prefix, so the model sees the direction change instead of silently losing the old rule. The checkpoint also carries a history map listing the most recent archived `history-N.md` files with their content topics, so exact wording can be recovered with the read tool instead of guessing which archive to open; older archives are collapsed into a count that names the range they cover. These changes make long sessions much more stable across repeated compactions.
- Compaction now preserves the newest user request and a larger verbatim tail after the checkpoint (about 5% of the context window, whole user turns first) instead of a small fixed slice, so the model does not lose what you last asked when the summary rewrites the older history.
- Request-level context reduction now protects failing command output that reports `FAIL` or `--- FAIL:` (the form Go and Rust test runners print), which could previously be summarized away even when it was the only failure evidence; the exact failure lines stay visible while the model works on them.
- A failed tool result stays complete until it ages past the error threshold: request-level reduction no longer summarizes failing output the model is still acting on, and LSP diagnostics summaries keep every location while capping thresholds to the configured policy.
- Request-level context reduction now keeps truncated-output artifact references verbatim: a `Full output saved to <path>` line reaches the model with its complete path instead of being clipped mid-string, so the model can read the saved output from the real path. Previously the path could be cut short and following the notice failed with `file not found`.
- Tool results that fit the inline budget are now returned in full on first use: many lines or one very long line no longer trigger truncation on their own, so the model sees the complete output instead of being pointed back at a saved artifact. The line and per-line limits now only shape the preview of an output that already exceeds the 50 KiB byte budget.
- Long streaming thinking cards no longer stall the UI: already-settled markdown and its per-line styling are rendered incrementally (each flush only processes the newly arrived deltas instead of re-rendering the whole accumulated text), and very large cards are exempt from disk spill so scrolling back across them stays smooth instead of repeatedly re-rendering the entire card.
- When a thinking-mode model (DeepSeek family) spends its whole output budget on reasoning and is truncated before producing any visible reply, the recovery request now replays the accumulated reasoning as a wire-only prefix so the model continues from where it stopped instead of restarting its thinking. The prefix is bound to the model that produced it: switching models or losing visible-reasoning support drops it safely, and it never enters the session history.
- The sidebar's `CHANGED FILES` section no longer collapses long lists behind an `… and N more` row: every changed file the sidebar still tracks is rendered and reachable by scrolling, since the info panel already scrolls. Entries are also newest-first now, so the most recent edits lead instead of sitting below the fold, and the per-agent cap on tracked files rose from 50 to 500 (oldest dropped first).
- Archived compaction histories (`history-N.md`) now open with a message index — one line per message segment: start line, block kind, a first-line snippet, and a `LARGE` marker for oversized tool output. The checkpoint wrapper tells the model to read the archive's index first and then only the line ranges it needs, so recovering an exact fact after compaction no longer means re-reading whole archives through truncation, which is what used to re-inflate the context right after a checkpoint.
- Switching to a model with a smaller context window compacts ahead of the move when the current context already crosses the new model's threshold: the switch starts the automatic compaction right away while the agent is idle, and with a turn active it defers the next main-model request until the compaction applies, so requests never run over the new model's compaction line (or risk its hard limit) right after the switch. A one-line status notice reports the compaction once it applies.
- The Codex low-quota context-surface freeze was removed. Chord no longer holds the previous request-level reduction, system prompt, and tool definitions in place once a tracked Codex quota window dropped below 10% remaining. That freeze existed only to keep a `stop_reason=tool_call` chain running to `end_turn` after the quota ran out, which is no longer how Codex behaves. Reduction and prompt/tool-surface refresh now take the same path at every quota level, so a newly enabled MCP tool, a permission change, or an updated memory file reaches the model on the next request instead of being withheld near the end of a quota window — the deliberate model/runtime mismatch that freeze accepted is gone. Enabling `/loop on` during an in-flight request no longer freezes that request's prepared prefix either; ordinary cross-turn stable-prefix reuse is unchanged and still keeps the prompt cache warm.
- `grep` now accepts a `patterns` list as an alias for `pattern`, matching a line when any of the listed patterns matches. Each entry keeps its own semantics: an entry that is not a valid regular expression is matched as literal text on its own, without turning the rest of the list into literal text, and one entry's inline flags no longer leak into the others. Empty entries are ignored, and a list of only empty entries is rejected rather than silently matching every line.
- An explicit `null` on an optional tool argument is now treated as if the argument had been omitted, instead of failing type validation. Models routinely fill every declared property, and a `null` that means "not provided" no longer costs a round trip; the tool result notes which arguments were ignored. Required arguments are unaffected: `null` there still fails with the type error that names the field.
- `chord cleanup` now ends with a summary line: how many sessions and empty project dirs were removed (counted separately, since an empty project dir holds only a leftover `project.json`) and the total bytes freed. Other kinds show a plain item count and total; dry runs phrase it as `would remove` instead of `removed`.
- SubAgents now inherit the main agent's YOLO mode while it is on: ordinary tools that would `ask` (file edits, shell commands) go through without raising the shared confirmation dialog, matching the main agent's own bypass. Inherited YOLO never relaxes `deny` (a read-only worker keeps its `write: deny`), and the protected control tools (`handoff`, `delegate`, `cancel`) still resolve through their rules and confirmations. The inheritance is live: switching YOLO off applies to a SubAgent's later calls immediately.
- New gateway-compatibility settings: `reasoning.effort_map` translates canonical reasoning-effort levels into the wire values a provider expects, `compat.chat_completions.infer_finish_reason` derives a normal `stop` / `tool_calls` completion for gateways that end the stream without `finish_reason` instead of treating it as interrupted, and `compat.chat_completions.requires_tool_result_name` / `requires_assistant_after_tool_result` adapt the tool-result shape that some compatible gateways reject.

### Fixes

- Restoring a session preserves the latest continuation of a delegated task and its saved result, rather than letting an older worker snapshot revert it to an earlier attempt.
- `notify` now exposes only the fields supported by the current role and rejects targeted replies from owner-only roles. Request replies require `correlation_id` and do not accept `subtype` or `payload`, so the tool schema no longer encourages calls that cannot be delivered.
- A delegated task whose wrap-up call misused the optional result fields is no longer destroyed. `complete` takes `result_type` together with `result` or `result_ref`, and supplying one side without the other used to end the task after a single correction attempt — discarding the summary, the changed-file list, and every other validated field over an optional piece of metadata. Once the correction budget is spent, that group is now dropped and the completion settles with the rest of the delivery intact, recording the drop as a remaining limitation. Every other rejection class still fails the task. The rejection message also names where the fields live (workers answered "result_type is required" by nesting `result_type` inside `result` and failing the identical check twice) and spells out the opt-out for completions that carry no machine-readable result.
- The status bar's token and cost readings for a focused worker no longer jump when it parks. A live worker was billed from its runtime instance while a parked one was summed across the task's instance history, so a task resumed for a second attempt hid its earlier attempts until the moment it stopped running; both sides now sum the task. The token total also came from two different accumulators that disagree about whether the prompt side includes the cached prefix (providers report their raw input field differently and only the usage ledger normalizes it), so the status bar now reads the ledger for every agent — the same frame as the cost pill beside it and the usage panel.
- SubAgents are now told that only the `complete` call reaches their owner. Without that, workers wrote the delivery twice, once as assistant prose and once as the call's arguments, and only the call was ever read.
- The sidebar's `AGENTS` section no longer collapses long lists behind a `+N more` row: every agent the sidebar still tracks is rendered and reachable by scrolling, since the info panel already scrolls. A session with more than ten agents previously dropped the tail entirely, so a still-running worker could be hidden once enough completed entries sorted ahead of it. The count is bounded upstream by `delegation.max_children`, so an expanded list stays within what the panel's own scrolling covers.
- The sidebar's `AGENTS` list now sorts a live SubAgent ahead of completed and waiting ones. The `running` state was missing from the sort order, so a worker that was actually executing fell into the default (lowest) bucket and sorted *below* completed agents — the opposite of "active workers first". `running` now shares the top priority with `streaming`/`executing`, and `error`/`failed` are pinned to the bottom alongside `cancelled`; the main agent is still forced to the top of the list regardless of its own state.
- Responses providers now send tool descriptions again. Every JSON function tool was declared with only its name and parameter schema, so the whole per-tool instruction layer (`todo_write`'s when-to-use rules, `done`'s required report structure, `read`/`shell`/`compact_context` semantics, and the documentation of every MCP tool, around 17 KB in a default setup) was silently dropped on OpenAI Responses and Codex OAuth transports while Anthropic and Chat Completions providers kept it. Loop-mode instructions that point at "the report structure in its tool description" therefore referenced text the model never received. The freeform `apply_patch` custom tool keeps its own Codex-exact description. Because the declared tool surface changes, existing prompt caches on those providers miss once and then refill.
- A freeform `apply_patch` custom tool no longer forces `parallel_tool_calls: false` on Responses requests, restoring the documented default of `true` for gpt-5-and-later models. The flag bounds how many tool calls one response may carry, which is exactly what the prompt asks the model to batch for independent read-only lookups; whether those calls then run concurrently is decided by the local tool pipeline, which already serializes dependent and side-effecting calls. Gateways that reject the combination can still set `parallel_tool_calls: false` explicitly per provider, model, or variant. Codex compaction requests keep omitting the field unless it is configured.
- Prompts, tool descriptions, and runtime instructions now name tools by their registered names (`` `done` ``, `` `todo_write` ``, `` `delegate` ``, `` `notify` ``, `` `complete` ``) instead of PascalCase spellings like `Done` or `TodoWrite`. Tool-name lookup is case-sensitive, so a model copying the prompt's spelling could emit a call the runtime does not recognize. Structural markers that are parsed rather than called (`Done rejected:`) and user-facing UI copy are unchanged.
- The SubAgent Task Closure prompt no longer tells a worker to escalate through `escalate` or `notify` when the role does not expose them. It now defers to the SubAgent Coordination section, which is rendered from the same visibility snapshot, so the two blocks can no longer contradict each other ("`notify` is unavailable in this role" next to "use Notify"). The "## Your Task" closing instruction resolves its escalation path from that same snapshot.
- Compaction checkpoints no longer fill up with false failures and file text. Successful tool output that merely contains the words `Error:` (source code, test data, a diff, or a search hit) was treated as a failing result, so ordinary reads and searches were preserved as "latest failing tool result", crowded the checkpoint's limited verbatim excerpt budget, and told the next continuation that several unresolved blockers existed. An explicit tool status now decides the outcome, and only transcripts old enough to predate stored statuses fall back to reading the text. Repeated failures are also capped, so one recurring error can no longer displace your latest request. Separately, a file attached with `@` is no longer classified as an instruction you gave: a plan or document containing wording such as "must" or "do not" previously turned into a standing constraint, and its text could reappear as a constraint long after the file was rewritten. File contents remain available as quoted evidence.
- The complete todo list now survives context compaction. The checkpoint asked the summarizing model to classify each todo by relevance, but nothing guaranteed it listed them all, so items could disappear from a long session while their work was still pending. Chord now writes the full pre-compaction list into the checkpoint itself, with the relevance grouping kept alongside it.
- The `edit` and `apply_patch` tools now share the same punctuation-tolerant fallback: when exact and trailing-newline matching both fail, full-width CJK punctuation (`,` `;` `:` `.` `!` `?` `(` `)`) and dashes are treated as equivalent to their ASCII forms, alongside the existing curly-vs-straight quote tolerance. A single space directly after a separator punctuation mark (or directly before a closing parenthesis), as well as a single inter-word space (`diff and` vs `diffand`), is treated as optional, so `：`, `: `, and `:the` match the same text. This covers models that tokenize `": "` as one token and re-emit it as `：` or drop the space. Unchanged context still keeps the file's original punctuation, ambiguous matches still error with "found N times", and all other whitespace (indentation, double spaces, tabs, quotes/dashes surroundings, newlines) stays significant — a real layout mismatch still fails with the fresh-read hint instead of silently applying a wrong edit.
- When the mismatch diagnostics still cannot pinpoint the failure, `edit` and `apply_patch` now locate the closest match and quote the exact file text: edit reports the closest block with the absolute file line plus the differing line relative to old_string, quoting the verbatim file and old_string text so a retry built from the hint can actually match; apply_patch points at the file line closest to a missing hunk line within that hunk's legal search window. Ambiguous tolerant candidates never get a closest suggestion that contradicts the ambiguity note, both scans are work-bounded (length pre-filter plus a rune-pair budget), and each falls back to the generic re-read hint when nothing clears a 0.6 similarity threshold.
- `apply_patch` hunk matching now applies punctuation/whitespace tolerance as one step instead of layering it into the exact-match cascade, so a tolerant match that lands in several places is rejected with the ambiguous lines named (`punctuation/whitespace-tolerant matching is ambiguous at lines 1, 3, 5`) instead of silently taking the first one. Combining trailing-whitespace and punctuation differences in the same line still matches, and `edit` and `apply_patch` mismatch hints now quote the file and model lines the same way, so trailing spaces and empty lines stay visible when the model copies a line to retry.
- Streaming a freeform `apply_patch` call no longer re-serializes the whole patch on every argument fragment. The canonical `{"patch": ...}` args object is built once the arguments are complete (which is the only point that reads it), removing a quadratic cost that grew with patch size (a 60 KB patch dropped from tens of milliseconds of serialization to roughly a tenth of that). The TUI's growing patch preview is unchanged.
- Cached LSP diagnostics from files other than the ones just edited are only attached when they are relevant, new, and fresh: they must share a directory with an edited file, each problem is reported once per session rather than repeated in every later tool result, and a file changed on disk since its diagnostics were published is skipped until Chord synchronizes it and confirms fresh ones. Later edits do not restate a problem the model already has (only changes are reported), while a problem fixed by another agent, a copy, or a `git checkout` restore stops being reported instead of being served from cache. Resuming a session recovers the suppression from the restored transcript instead of re-announcing diagnostics that are already visible in it.
- When `edit`, `write`, `apply_patch`, or `delete` detects that a file changed on disk since the model's last observation, the drift warning now says how long ago the change happened (for example "about 45s ago"), so the model can tell an active external writer apart from a settled state. The age is named only when the call touches a single file (with several, one file's timestamp would mislead about the others) and is best-effort: it is only shown within 24 hours and never for timestamps predating the runtime start, which for a resumed session is later than the session's own start.
- Tool cards now use a `▸`/`▾` disclosure marker instead of textual expand hints, and collapsed cards no longer print line-count summaries (`N more lines`): the marker is the single indicator that `Space`/`Enter`/`o` toggles the card. Default card states changed: completion reports (`complete`/`escalate`) and delegated task cards render expanded by default, local `!` shell cards are expanded once output arrives, and every other tool card starts collapsed (write/edit/apply_patch still expand when their result arrives).
- Terminal notifications now follow runtime lifecycle boundaries: a completion reminder fires only after real agent work fully stops across the main agent and all SubAgents, queued input keeps the runtime silent while work continues, and explicit user-input waits (permissions, questions, Handoff, and loop decisions) notify immediately. Session, model-pool, MCP, and other control actions that settle into idle no longer announce "Ready for input". Idle still reaches runtime and headless consumers; user-input waits also use an explicit `notification` event.
- Local terminal cards no longer show a phantom hidden line when command output ends with the usual newline, so `[space]` is only advertised when expanding reveals real content. Copying cards with `yy` now labels local commands as `TERMINAL (!):` rather than `User:`, and multi-card copies preserve `User:`, `Assistant:`, terminal, and tool boundaries consistently.
- Resuming a session no longer degrades local terminal runs whose output ends with a newline into plain user messages. `/export` also writes those runs in the same clean `TERMINAL (!)` format instead of leaking the machine-readable payload record that only exists for restore.
- Card copying now covers every card type consistently: `ERROR`, status, and boundary cards carry explicit labels instead of bare text, `skill` cards copy as name/path/body rather than raw JSON arguments, and tool results keep `[image: ...]` placeholders for attached images.
- Jumping with `(`/`)` (matching bracket blocks) and `j`/`k` (focused block navigation) no longer snaps back to the bottom on the next streaming update: moving the viewport away from the tail now stops tail-following, so the position you jumped to stays put while the agent keeps running. Landing at (or scrolling near) the bottom keeps following as before.
- Manual model-pool switches no longer emit a generic model-switch toast or terminal idle notification. Runtime and headless idle events remain delivered so local and remote clients can clear their busy state, while fallback and real task-completion notifications are preserved.
- Failed `edit` tool cards now render `old_string → new_string` as a syntax-highlighted requested replacement with deleted/added line backgrounds, instead of flattening multiline code into escaped JSON. `replace_all` and the actionable error remain separate, and copying the card still preserves the exact untruncated strings.
- Edit tool cards no longer drop or blank lines in unequal change blocks. When a hunk replaced two lines with one (or one with two), the leftover delete/add line lost its whole-line background or disappeared from the diff view entirely.
- The `apply_patch` tool card now names what each section is: the planned file list is `Targets:`, the committed part of a partially applied patch is `Applied changes:`, and the submitted input is `Requested patch:`; a successfully applied diff is shown directly without a section label. A partially applied patch separates its applied summary, `Error:` text, and `Diagnostics:` into ordered sections instead of running them together, and stops repeating the requested patch that the diff above already shows. Target, operation, and patch lines are truncated with `…` rather than wrapped, so one file or one patch line stays on one row and the card structure survives a narrow terminal; copying the card (`yy`) still yields the untruncated text. When the model returned only text, or a stream was cut by a transient transport error, or a completion was rejected for invalid arguments, Chord sends one bounded recovery request — but the in-flight request gate had already been cleared before that request was launched, so the event loop treated the SubAgent as idle: it could dequeue a waiting user message and start a new turn, which cancels the recovery request, or park the SubAgent outright. Header truncation now uses ANSI-aware truncation that preserves the tool name's color and weight, so every tool name (MCP or built-in) stays blue/purple and bold at any width.

Reasoning can consume the entire output budget, leaving a response with no tool call and no visible text; the existing truncation recovery only engaged when a malformed tool call was present, so this shape fell through to the ordinary "no tool calls, go idle" path with no warning, no error, and nothing rendered — the transcript just stopped after a thinking card. Chord now retries such a response with a recovery prompt that steers the model to act instead of reasoning further (bounded by the same two-attempt limit), and reports an explicit error if the limit is hit repeatedly. Automatic compaction is deliberately not attempted for this shape because the cause is the output budget, not oversized input. A truncated response that did carry text keeps that partial reply and now warns that it is incomplete.

The notification text scanned back for the most recent assistant or error block, so a turn whose reply never materialized (for example the output-limit truncation above) was announced with mid-turn narration from earlier in the same turn — often a sentence ending in a colon, reading as "still working" rather than "stopped, waiting for you". The scan now stops at tool and user blocks, falling back to the neutral ready message when the turn produced no reply of its own.

Such gateways interleave content blocks (thinking deltas, then a whole tool call, then the rest of the *same* thinking block), and starting the tool card used to settle and detach the in-flight thinking card, so the remaining deltas opened a second card, usually breaking mid-word. A thinking card now stays attached until its own `thinking_end` arrives, which also keeps the reported thinking duration covering the whole block instead of only the resumed tail. Genuine terminal points (turn end, cancellation, errors, idle) still settle an unended thinking card and compute the fallback duration as before.

Only main-agent roles other than the active one are offered, and an approval naming an unavailable target (including from a headless client) or one whose execution preparation fails records an error on the card instead of success. The time you spend reading the plan and choosing a target is counted under `User wait` in the TIME panel (never under `Tools`), and the headless `handoff` command gains a distinct `cancel` action alongside `accept`/`deny`.

When every file group fit the rendered list but the trailing "other lines omitted" marker did not fit the byte budget, the marker disappeared and the summary looked complete; already-rendered groups are now reclaimed to make room, so the summary always reports how many files, matches, and other lines were omitted.
- Repeated-call matching in context reduction only trusts results that visibly succeeded: a failed attempt no longer masks an earlier successful run of the same call, and large integer arguments keep their exact identity during canonicalization.

Chat-completions bodies omit `parallel_tool_calls` and `tool_choice` when no tools are declared, messages (Anthropic) and generateContent (Gemini) skip `tool_choice` / `toolConfig`, and ordinary Responses generation bodies skip `parallel_tool_calls` / `tool_choice` the same way. Native Codex compaction keeps its dedicated wire contract. The per-line indent widths used to translate screen columns back into text were stored shifted down by the card's bottom padding and margin, so each line was measured against a neighbouring line's indent: selecting inside a code block whose nearby line had soft-wrapped (the wrap adds a hanging indent) copied the text without its first two characters, and double-click word selection picked the wrong word bounds on those lines.

Stopping a parked worker whose attempt changed concurrently now reports the conflict and suggests a retry instead of claiming the task disappeared, and a cascade cancel that loses a settlement conflict now pins the runtime to the settled terminal state so it can still be parked.

Writes racing an intentional close during shutdown or switch no longer mint a false degradation against the next session.

Previously a sweep that won that window was silently overwritten — the registry reverted to a live attempt whose cancel settlement already existed, so the task's later real completion could never be recorded. A revival that loses the race now reports the conflict, and retrying starts a fresh attempt.

- A model sometimes emits an orphaned variation selector (U+FE0F/U+FE0E) not attached to a base emoji. The width library counts the lone selector as 1 column, but the terminal renders it zero-width, so card backgrounds under-fill by that column and the terminal's default dark surface shows through on the right edge; the same stray selector also breaks markdown tables (the dropped base emoji can drag a cell delimiter with it) and makes edit-tool matching fail when it lands inside `old_string`/`new_string` (e.g. `️0` instead of `0`, or `️12, ️45` instead of `12, 45`), because the file content never contains it. - `chord import codex --id <id>` now resolves the id `codex resume` prints on exit. A Codex session that had spawned a forked or sub-agent thread left a second rollout file whose records still named the parent session, so importing that id matched two files and aborted with "multiple files matched". The lookup now identifies a rollout by the thread id Codex itself uses for `codex resume <id>`, so resumed or forked sessions import directly instead of requiring an explicit file path.
- Two events acting on the same SubAgent mailbox at once (a delivery racing a concurrent rebuild, or a task claim settling while another event mutates the same queue) could previously lose, duplicate, or reorder a message. Queue state now advances in a single serialized order on every in-memory path, closing the accesses that bypassed the mailbox's lock, so those interleaved unsynchronized writes can no longer happen.
- A notification that reaches a SubAgent after its task has already settled (completed, failed, or cancelled) is now dropped instead of flipping the settled task back to running. Durable terminal outcomes settle the runtime before a queued or late event is dispatched, and reviving the task would bypass the explicit new-attempt machinery that reusing a terminal task requires; a parked or idle worker still resumes on notification as before.
- Resuming a session no longer re-delivers a SubAgent mailbox message that already reached the main transcript. A report is appended to the main conversation at request dispatch, but its consumed acknowledgement is only written at turn teardown, so a crash inside that window used to replay the report after restore and make the main agent act on the same result twice. Restore now treats an unconsumed-but-appended message as already delivered, ending the at-least-once delivery window at the durable transcript row.
- A SubAgent mailbox message written while the mailbox log was being compacted or rebuilt on restore no longer stays undelivered until the next restart. A stale snapshot of the index that routes persisted messages back into the inbox used to drop such a late append; the index now publishes under a write generation, so a snapshot taken before the append is discarded and rebuilt, and a write that lands after the snapshot registers itself instead.
- An undelivered SubAgent mailbox notification no longer disappears when context compaction archives the transcript rows that carried it. A notification the main agent has already seen is settled (its consumed acknowledgement written) before the rows disappear, and one never presented to the model is re-queued for delivery after the checkpoint commits — so a worker's update survives a compaction that lands between its delivery and its acknowledgement, instead of being lost with its only delivery evidence.
- A targeted `notify` you sent a delegated worker now persists with its routing metadata and is restored as the same status card after a restart or session switch, matching how worker-to-owner reports were already restored.
- Context-summary cards no longer end with the line `Press toggle-collapse to expand and inspect the full preserved context message.` Compaction summary cards are always fully expanded (the `Space`/`Enter` toggle does not apply to them) so the instruction pointed at an action that does nothing. New checkpoints drop the tail, and the card hides it in checkpoints written by older versions.

- Undelivered progress updates from a worker are no longer dropped. A newer update for the same worker used to replace an earlier one that had not been delivered yet, and the mailbox log's periodic cleanup kept only the latest progress row per task, so you could miss everything that happened between two reports and see only the final status. Every undelivered update is now kept (in memory and in the durable log) and delivered in the order the worker produced it.
- `spawn` results are queued durably before their card appears. While the owning agent is mid-turn, a result stays queued and is delivered at the next request boundary, so a restart does not lose it, and the `JOB RESULT` card is built only after the result message has been durably appended to the transcript, so a running session and a restored one show the same cards. Each finished background object appends its own result message instead of being merged into a single entry.
- A SubAgent completion or notice card is rebuilt from the persisted mailbox record, so a running session and a restored one show the same card.
- Input queued while the agent is busy is not stranded when a turn is interrupted or the agent waits on a user decision such as a Handoff. The queued messages keep their arrival order and ride the next request that actually goes out (a request started by a background notification carries them too), and a waiting queue does not by itself keep the agent from going idle, so the control plane sees `idle` while the input waits.
- The repository status line is now part of every LLM request instead of only the first one of each process. Chord prepends "is this a git repository" and the current branch to the first user message without persisting it, but the injection was treated as a once-per-process action: from the second request onward the message head no longer carried it, so the provider's prompt cache missed from the first user message and the whole conversation was paid for again as uncached input. Every `--resume` and session switch re-armed the same one-shot guard, so a long session or a resumed one usually ate a full-context uncached request right after starting. The status is now injected into every request and skipped when the reused prefix already carries it, so the prompt prefix stays byte-stable; the injected text is only the repository yes/no answer and the branch, which practically never changes within a session.
- A read result that a later edit or reread made stale is no longer rewritten in the already-sent prompt prefix the moment it is detected. The reduction saves a few tokens, but rewriting a message that already sits inside the provider's cached prefix invalidates that cache from that point on and re-bills the rest of the conversation as uncached input — which happened even when the saving could not come close to paying for it. Stale reads now wait for the same amortization gate as every other reduction, so they apply on a cold cache or when a flush is justified; a read that already carries the stale/superseded note is left byte-stable instead of being re-rendered to an equivalent one.

## 0.7.3 - 2026-08-08

### Breaking Changes

- Context reduction no longer accepts `context.reduction.high_pressure_usage` or `force_prune_usage`; request-batch age thresholds now determine when output is reduced. Remove those keys from existing configuration files. Chord reports a migration error instead of silently ignoring them.
- The `patch` tool is replaced by `apply_patch`, which speaks the Codex `*** Begin Patch` envelope and applies multi-file Add/Update/Delete/Move operations as one transaction: every file is planned from a single filesystem snapshot, revalidated (content and file mode) before commit, and rolled back as a unit (including the file whose own write failed) when any commit step fails. Repeated plain `*** Update File:` sections for the same normalized path follow Codex ordering semantics: each section patches the previous section's in-memory result, then the original-to-final change is committed as one file mutation; a later mismatch therefore leaves the workspace unchanged rather than exposing Codex's partial-write behavior. Compatibility is preserved: the legacy `patch` tool name and single-file `{path, patch}` arguments keep working, and `patch` permission rule keys normalize to `apply_patch` at parse time. Permission patterns now match every path a patch touches, lexically cleaned so `./secret/x` cannot dodge a `secret/*` deny, and `*** Delete File:` operations still honor tool-specific `delete` rules. Deleting a file no longer requires a prior complete read — path resolution, permission rules, tracked locks, and pre-delete backups carry its safety instead.
- Configuration loading now rejects unknown YAML fields at every level (top-level, provider, model, `context`, `compat`, and nested blocks) instead of silently ignoring them. Keys that older Chord versions tolerated (typos, or fields from a newer version after a downgrade) now prevent startup with an explicit parse error naming the offending field; remove or fix such keys before upgrading. Empty and fully commented-out config files still load as before, and the `model_templates` top-level key is reserved as a pure YAML-anchor namespace.

### Improvements

- Model setup now uses the conservative Codex-specific GPT-5.6 limits (`400000` context / `272000` input / `128000` output) and keeps the GPT-5.4 input limit aligned at `950000`. Model recipes use the same GPT-5.6 default for Codex-backed relays and explain how to opt in to the full 1.05M OpenAI API window manually. Provider configuration supports provider-level `parallel_tool_calls` and exposes opt-in wire compatibility toggles for Responses and Chat Completions gateways.

- Tool results now carry one-shot efficiency hints when a turn drifts into serial single-lookup rounds or repeated small-window reads of a file that fits in a single read, re-surfacing the batching and whole-file-read guidance at the moment it applies. Failed test commands that died in their build or setup phase now steer to a build-only check first, and shell-timeout errors explain how to narrow or background the next attempt.
- Shell tool results append a concise wall-clock elapsed-time note once a command crosses the slow-command threshold, so the model can factor real cost into choosing what to run next; sub-second commands stay unannotated.
- Reasoning replay is now optimistic with per-target adaptive degradation: chat-native reasoning and protocol-native items (Responses encrypted reasoning, Anthropic thinking blocks, Gemini thought signatures) are first replayed to any target speaking the same wire protocol, including cross-provider fallback. A target that rejects such a payload is downgraded for the rest of the session (first to strict provenance matching, then to textified history), so an incompatible backend costs at most two failed attempts per session instead of losing reasoning continuity on every fallback.
- New opt-in `compat.reasoning_continuity.mode: anthropic_unsigned` for Messages-compatible endpoints (e.g. DeepSeek/GLM) that return visible unsigned thinking blocks: such thinking is replayed natively only to the same configured provider/model. Visible OpenAI Chat `reasoning_content` can also be converted into unsigned Anthropic thinking when the target exposes that structured carrier, keeping reasoning visible without fabricating signatures. Cross-provider or rejected replay preserves the completed tool round but drops reasoning when the target cannot carry it structurally, rather than leaking it into assistant text.
- MCP tool calls now show a compact summary of the arguments generated by the model on their TUI card header: scalar values remain visible, JSON values are summarized as `{N fields}` or `[N items]`, and long values are truncated. MCP server launch arguments and environment variables are separate from model-generated tool-call arguments and are not added to the card.
- Usage accounting is now normalized across protocols: the top-level input count is treated as the complete prompt (including separately reported cache reads), and the post-response context baseline counts input plus cache-write plus output tokens, so compaction thresholds, input-budget displays, and usage statistics agree regardless of how a provider splits cache buckets. New `compat.usage.input_includes_cache_read` and `compat.usage.input_includes_cache_write` overrides correct gateways whose usage fields differ from their declared protocol, and cache-aware fallback pricing now uses the exact token-weighted cache hit rate observed per model ref in the current session. Usage statistics use the current `usage.jsonl` ledger format; an invalid or stale `usage-summary.json` is rebuilt from the ledger.
- The todo list may now carry multiple `in_progress` items while the agent is genuinely switching between distinct active workstreams, each with a unique `active_form`; work that is only planned, blocked on prerequisites, or waiting to start must stay `pending`.
- Context reduction now shields diff and patch evidence with a dedicated `diff_protect_age_turns: 12` threshold and, when pruning old diff/patch output, preserves files, hunks, change counts, and bounded representative lines instead of a generic omission marker.
- `apply_patch` hunk matching gains a final punctuation-normalizing fallback for any text-decodable file: Chinese and ASCII punctuation are treated as equivalent, applied only when the complete hunk has exactly one unique match, keeping the file's own punctuation in unchanged parts and reporting its use in the result; ambiguous matches are rejected. "Hunk not found" errors now report `(N/M)` progress plus a short expected-line preview, and explain when the text occurs only inside a longer line.
- Not-found path suggestions now search the working tree root for relative requests made from a marked project directory, and scoring requires a plausible typo distance so unrelated files stop being suggested.
- `apply_patch` results now run the same post-write LSP diagnostics flow as `write` and `edit`, reporting diagnostics in a unified format.
- Models with native `apply_patch` support no longer see the `write` and `delete` tools: `apply_patch` is their sole write/delete surface, while models that rely on fallback editing keep both. Explicit `delete` permission rules still govern `*** Delete File:` operations, including wildcard and narrower glob layering.
- Completed tool cards now show the wall-clock execution duration of the finished call.
- Terminal notifications can now also fire while the TUI is focused: the new `desktop_notification_foreground: true` option (default) notifies regardless of focus, and `false` restores background-only notifications. Chord auto-selects the OSC 9 / OSC 777 escape sequence by terminal, and the terminal decides whether the notification also produces a sound.
- SubAgent completion verification records (for example `go test ./... [failed]: exit 1`) now persist through task restore and compaction and render consistently in the TUI; resumed continuations are gated when provenance is unknown.
- Delegated task coordination is now durable: immutable settlements, task groups, mailbox payloads, and parent-child request/response state survive compaction and restart. `notify` gains a `response` message type with `target_task_id` and `correlation_id` for structured replies, peer routing via `notify_peer` is constrained to live sibling tasks, and delivery stays idempotent across task rehydration.
- Compaction now emits structured analytics events for provenance and lifecycle stages (source-ref counts, durations, failure classes) for diagnostics.

### Fixes

- Still-valid `read` outputs are never trimmed by request-level context reduction anymore. Previously a read older than a few turns and larger than the read-like size threshold was summarized even when it was still the model's only current view of the file, forcing paged re-reads or summary-based guessing while the context was nowhere near its limit. Reduction now trims a read only when it is provably outdated (`truncated=stale` after a file mutation) or duplicated later in context (`truncated=superseded`); a still-valid read is kept regardless of age, size, or how many parallel reads share one batch, and capacity pressure remains durable Compaction's job. Re-reading is the natural recovery — no machine-readable recovery metadata is emitted. `context.reduction` additionally accepts a boolean shorthand: `false` disables request-level reduction entirely (previously a parse error), `true` keeps defaults; unknown reduction keys are now rejected instead of being silently dropped.
- Whole-file `write` authorization now binds a complete `read` or `<file>` reference to the exact bytes shown to the model. Partial/stale file references, files changed while a read is completing, and relative paths under a SubAgent working directory can no longer authorize replacement of an unseen version. `delete` is deliberately path-authorized instead of read-gated (see the `apply_patch` entry above), so removing a file no longer forces a wasteful full read first.
- Cross-provider and cross-protocol fallback no longer erases completed tool history when native reasoning cannot be replayed. Chord now preserves structured call/result pairs across Chat Completions, Responses, Messages, and Gemini; converts action-bound visible reasoning or public summaries only when the target exposes a structured reasoning carrier; and textifies completed tool rounds only after a target rejects the structured shape. Unsupported reasoning is dropped instead of being injected into assistant-visible text. Fallback provenance now records the actual running target's wire family, and normalization logs expose before/after message counts plus downgrade/drop counters.
- Fixed model-change events being droppable and a shutdown deadlock when the event loop blocks on a full output channel: running-model changes are now delivered reliably, Shutdown releases blocked output sends immediately and waits for the loop to fully stop before checkpointing SubAgents and saving the final recovery snapshot, and persist/compaction drain timeouts are reported as errors instead of continuing with a possibly inconsistent state.
- The `edit` tool now tolerates curly/straight quote variants as a last-resort fallback: when exact and trailing-newline matching both fail, `old_string` is re-matched with quote punctuation normalized, applying an intent-preserving replacement that keeps the file's original bytes for unchanged context. This fixes the dominant edit failure with models that cannot reproduce curly quotes verbatim. The deprecated `filePath` argument is also accepted as an alias for `path` (mirroring Glob/Grep).
- Background `spawn` completions now always leave a result card in the main transcript. Cards for the main agent's own background work carried an agent attribution the main view filters out, so only the toast notification was visible; completions arriving while Chord was idle emitted no card at all before the follow-up reply; and the card could still be dropped when the UI event channel was saturated. Results whose owning SubAgent no longer exists are now shown in the main transcript instead of a view that can no longer be opened. Completed background work now renders as a dedicated JOB RESULT card, persists as a structured background-result message that survives session restore, and its completion toast level reflects the outcome (cancelled, failed, or success).
- SSE and WebSocket stream events without an explicit HTTP status are no longer guessed as 4xx/5xx: each `APIError` records its origin (`http_response`, `sse_event`, or `websocket_event`), an unknown Codex WebSocket status is preserved instead of being coerced to 500, and stream events stay retryable unless an explicit request, auth, context, or replay signal applies. Transient provider capacity signals ("overloaded", rate-limited, temporarily unavailable) no longer enter the reasoning-replay degradation ladder, and a model that echoes internal replay evidence instead of continuing the task is detected and treated as a replay failure.
- LSP `workspace/applyEdit` requests are now rejected outright: a language server can no longer ask Chord to apply arbitrary workspace edits, and no file writes happen on that path.
- LSP review snapshots now rebuild correctly for `apply_patch` calls: durable file-state metadata identifies each written, moved, or deleted path, and every review snapshot records its own path so per-file diagnostics remain accurate across restore and compaction.
- Failed SubAgent tool results are now durably flushed before the terminal close path can observe the failed instance, so restore and export always see the persisted error results.
- Malformed-call, compaction, and terminal-recovery retries are now bounded, and failed partial output is discarded before replay. SubAgent shell evidence is verified after restore while model-pool and quota fallback behavior is preserved.
- TUI apply_patch path summaries now show a `D` marker for delete operations.
- A no-op `apply_patch` with no net file changes now reports `No net file changes` instead of an empty diff.
- MCP tool cards now keep the model's original arguments: the header summary reflects what the model actually generated and is no longer overwritten by the effective payload after a hook or confirmation rewrote the arguments, and execution-state updates no longer replace the recorded call on recovery cards.
- SubAgent MCP servers are now closed even when shutdown times out: cleanup is deferred until the agent run exits, so MCP transports no longer leak when the shutdown budget expires.
